# teofunk-projects

Все проекты Teofunk в одном приватном репозитории: исходники, история версий, правила работы.

## Карта

Карта предварительная. После инвентаризации папок на Mac она будет уточнена.

| Папка | Что внутри |
|---|---|
| `kozlovclub/plugins/` | плагины WordPress для живого kozlovclub.ru (поиск, афиша, календарь, «Живой фасад», разметка концертов, Kozlov TV, StreamVi, новогодняя страница, счётчик кэша и другие) |
| `kozlovclub/new-site/` | новый сайт клуба 2026: тема Kozlov Club 2026, Kozlov Core, Kozlov Import и их модули |
| `kozlovclub/tools/` | скрипты и сервисы клуба: календарь памятных дат джаза, барометр, автоматизации |
| `kozlovclub/apps/` | приложения клуба: «Козловск», Джаз-навигатор и другие |
| `jazzartclub/` | новый сайт jazzartclub.ru |
| `keramichnaya/` | тема сайта keramichnaya.ru |
| `apps/` | приложения для Mac: SmartFind, Holler Box, Reel Practice |
| `docs/` | ТЗ, спецификации и брифы (только текст) |

«Ежедневная Джазета» хранится в отдельном репозитории [Teofunky/jazzeta-pipeline](https://github.com/Teofunky/jazzeta-pipeline): у неё свои автоматические проверки и выпуски.

## Что сюда не кладём

- пароли, ключи API, `wp-config.php`, `.env`;
- дампы базы (`*.sql`): в них данные гостей клуба;
- фото, видео и медиатеку сайта;
- собранные ZIP: их собирают из исходников и прикладывают к выпуску (GitHub Releases).

Перед каждым коммитом запускается проверка `scripts/check-secrets.sh`. Чтобы она срабатывала сама, один раз после клонирования выполните:

```bash
git config core.hooksPath .githooks
```

## Версии

Каждая выпущенная версия отмечается тегом `<папка>/v<версия>`, например `kozlov-calendar/v1.0.3`. Старые версии из архива импортируются коммитами по порядку, поэтому по истории видно, что менялось от версии к версии.

## Как работать

- В чате Claude: попросить «возьми плагин X из teofunk-projects», и Claude клонирует репозиторий в свою сессию.
- В Claude Code (вкладка Code в приложении для Mac): открыть папку репозитория, правила из `CLAUDE.md` подхватываются сами.
