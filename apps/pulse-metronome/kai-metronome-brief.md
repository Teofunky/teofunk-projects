# PULSE — Метроном и тюнер в стиле Kai Krause
### Дизайн-бриф, промпт и план разработки

---

## 0. Что мы делаем и почему так

iOS-приложение: **супер-удобный метроном** (главное) + **гитарный тюнер** (второе). Визуальный язык — наследие Kai Krause / MetaCreations (KPT, Bryce, Power GOO, Photo Soap, Power Show), но переосмысленное в современный, чистый, тактильный UI/UX 2026 года.

**Ключевая идея фишки:** мы берём не «глянцевую картинку» Kai, а его *язык взаимодействия* — и снимаем его главный недостаток.

Что мы заимствуем у Kai:
- **Раскрытие по требованию** — управление набирает контраст при касании, в покое уходит в фон, чтобы не отвлекать от ритма.
- **Drag-управление вместо слайдеров** — параметры крутятся жестом прямо по «орбу», а не ползунком.
- **Комнаты** — отдельные специализированные пространства под одну задачу (Метроном / Тюнер / Пресеты).
- **Memory Dots** — точки-ячейки для мгновенного хранения и вызова пресетов.
- **Прозрачность, мягкие тени, свечение** — целостная гармоничная среда (kansei), сложное спрятано за игровой простотой.

Чего мы у Kai НЕ повторяем (его известная слабость): орбы Kai не показывали точное значение и по ним нельзя было ввести число. Для метронома это недопустимо — **точный BPM всегда виден и точно выставляется**. Это и есть «Kai, но современный»: тактильность Kai + точность и доступность сегодняшнего дня.

## 1. Правильная последовательность действий

```
ЭТАП 1  Концепт + спека         → этот документ (готово)
ЭТАП 2  Звучащий прототип       → артефакт в Claude (HTML/React + Web Audio)
ЭТАП 3  Нативный iOS (SwiftUI)  → Claude Code + Xcode (звук через AVAudioEngine)
ЭТАП 4  Тест на устройстве      → джиттер тайминга, доступность, жесты
ЭТАП 5  App Store               → подпись, ревью, приватность
```

**Почему именно так, а не «сразу в код»:**
- Прототип в браузере даёт почувствовать UX и ритм взаимодействия за минуты, без затрат на Xcode. Здесь рождается «мегаудобство».
- Но веб-прототип ≠ приложение: Web Audio в вебвью даёт нестабильный тайминг (джиттер), а метроному нужна сэмпл-точность. Поэтому финал обязательно нативный.
- Claude отлично делает прототип, SwiftUI-скаффолдинг и итерации; production-стадия (точность звука, ревью, доступность) требует ручного контроля и, возможно, разработчика.

**Что понадобится для Этапа 3:** Mac с Xcode (без него iOS не собрать и не подписать) + Claude Code в терминале (или интеграция Claude прямо в Xcode).

## 2. Архитектура «комнат» (экраны)

### Комната 1 — METRONOME (главная, открывается по умолчанию)
Центр экрана — **большой пульсирующий орб** (это и есть «сердце» Kai). Вокруг — кольцо акцентов по числу долей. В покое периферийные контролы притушены; при касании всплывают.

Контролы:
- **BPM** — крупное число в центре, всегда читаемо. Изменение: вертикальный drag по орбу (грубо) + кольцо точной подкрутки (±1) + tap-tempo по орбу.
- **Размер (time signature)** — отдельный «лепесток», раскрывается в выбор: 4/4, 3/4, 6/8, 5/4, 7/8, 9/8 и кастом (числитель/знаменатель крутятся drag'ом).
- **Сабдивизии** — восьмые, триоли, шестнадцатые: визуально как «деление» долей внутри кольца.
- **Акценты** — тап по любой доле в кольце меняет силу: акцент / норма / тихо / пауза.
- **Звук клика** — выбор тембра (вуд-блок, мягкий, цифровой), drag по «орбу тембра».

### Комната 2 — TUNER (гитарный тюнер)
Центр — **горизонтальная шкала-стрелка** со свечением: ушёл от ноты — холодный синий, в точке — тёплое золотое свечение (привязка к Soap). Крупная буква ноты по центру. Под ней — пресеты строёв (Standard E, Drop D, Open G и т.д.) как memory dots.

### Комната 3 — PRESETS / MEMORY DOTS
Сетка точек (как 3×3 у KPT). Долгий тап — сохранить текущую настройку метронома; короткий — мгновенно вызвать. У каждой точки — мини-превью (BPM + размер), решает старую проблему Kai с отсутствием обратной связи у memory dots.

**Переход между комнатами:** не вкладки снизу, а жест/притушенные иконки по краю, всплывающие при касании — в духе MouseOver Kai. Только одна комната активна за раз.

## 3. Дизайн-язык (токены)

**Темперамент: гибрид** — тёмная глубокая база Bryce/KPT + тёплое свечение акцентов из Photo Soap.

| Токен | Значение | Назначение |
|---|---|---|
| `--bg-deep` | глубокий сине-чёрный градиент (радиальный, к центру светлее) | фон-«космос» |
| `--orb-base` | тёмный графит с внутренним объёмом | тело орба |
| `--glow-warm` | тёплое золото/янтарь | акцент доли, попадание в ноту, активные элементы |
| `--glow-cool` | холодный циан | неактив, «мимо» в тюнере |
| `--text-primary` | почти белый, высокий контраст | BPM, нота — всегда читаемы |
| `--surface-glass` | полупрозрачные панели с blur | всплывающие контролы |

Принципы:
- **Тени мягкие и реальные** — каждый элемент отбрасывает свет/тень, как у Kai.
- **Свечение = состояние** — золото на удар доли, пульс синхронен звуку.
- **Вспышка с острой атакой (для Claude Design)** — на каждую долю орб вспыхивает мгновенно (атака ~0мс) и быстро затухает (~120мс), повторяя форму звукового транзиента. Акцентная доля вспыхивает заметно ярче обычной. Глаз и ухо бьют в одну точку (kansei-целостность Kai). Даже если в прототипе звук условный — анимация пульса живёт в темпе BPM и с этой острой формой.
- **Контрол спит — контрол просыпается** — opacity 0.35 в покое → 1.0 при касании, плавно (~200мс).
- **Drag, а не slider** — но с числовым фидбеком рядом (наше отличие от Kai).
- **Тактильность** — haptic feedback на каждый удар и переключение (на iOS).
- **Типографика** — крупная, геометрическая, с большим запасом по размеру для BPM/ноты.

## 4. ГОТОВЫЙ ПРОМПТ для генерации интерактивного прототипа

> Скопируй этот промпт в новый запрос к Claude (или используй прямо в этом чате), чтобы получить рабочий звучащий артефакт.

```
Создай интерактивный прототип iOS-метронома в виде одного HTML/React-артефакта,
который реально звучит и работает. Это прототип для проверки UX перед нативной
разработкой на SwiftUI.

ЭСТЕТИКА: язык интерфейсов Kai Krause / MetaCreations (KPT, Bryce, Power GOO,
Photo Soap), но современный, чистый и тактильный. Тёмная глубокая база (сине-чёрный
радиальный градиент-«космос») + тёплое золотое свечение акцентов. Мягкие реальные
тени, полупрозрачные стеклянные панели с blur, объёмные «орбы».

ГЛАВНЫЙ ЭКРАН — МЕТРОНОМ:
- В центре крупный пульсирующий орб. На каждый удар доли он вспыхивает тёплым
  золотым свечением синхронно со звуком. Внутри орба — крупное число BPM, всегда
  чётко читаемое (это критично, в отличие от оригинальных орбов Kai).
- Вокруг орба — кольцо точек по числу долей в такте. Активная доля подсвечивается.
  Тап по точке меняет её состояние: акцент / норма / тихо / пауза.
- BPM меняется: вертикальным drag-жестом по орбу (грубо) И tap-tempo по орбу.
  Рядом всегда видно точное число.
- Кнопка размера такта раскрывается (unfolding) в выбор: 4/4, 3/4, 6/8, 5/4, 7/8,
  9/8 и кастом. Поддержи сложные размеры.
- Сабдивизии: восьмые / триоли / шестнадцатые.
- Периферийные контролы в покое притушены (opacity ~0.35) и набирают контраст
  при наведении/касании — в духе MouseOver Kai. Плавные переходы ~200мс.

ЗВУК:
- Используй Web Audio API (НЕ setInterval для тайминга — используй scheduler с
  look-ahead через AudioContext.currentTime, чтобы клик был ровным).
- Разные тембры для акцента и обычной доли.
- Точность тайминга — приоритет №1.

ВТОРОЙ ЭКРАН — ТЮНЕР (заглушка визуала, без реального микрофона в прототипе):
- Горизонтальная шкала со стрелкой. Мимо ноты — холодный циан, попадание — тёплое
  золотое свечение. Крупная буква ноты по центру. Пресеты строёв снизу как точки.

ПЕРЕХОД МЕЖДУ ЭКРАНАМИ: не нижние вкладки, а притушенные иконки по краю, всплывающие
при касании. Одна «комната» активна за раз.

ТЕХНИКА:
- Запусти без localStorage/sessionStorage (не поддерживаются в артефактах) — храни
  состояние в React state.
- Сделай адаптивно под вертикальный экран телефона.
- Добавь мягкие тени и свечения через CSS (box-shadow, filter: drop-shadow).
- Не используй <form>. Только onClick/onChange/onPointer-события.

Сначала покажи мне рабочий метроном, потом будем итерировать по деталям.
```

## 4а. ЗВУК (для Claude Code, НЕ для Claude Design)

> Claude Design делает визуал и интерактив — реальные звуки ему не нужны. Весь этот
> раздел — для нативного этапа (Claude Code + Xcode), где звук собирается по-настоящему
> через AVAudioEngine. Проверять ровность клика лучше в звучащем артефакте.

### Откуда брать звуки (по чистоте прав)

1. **Свои записи (рекомендуется).** Метроному нужны очень короткие транзиентные звуки —
   их легко записать самому: дерево о дерево, клаве/палочки, рим-шот по ободу барабана,
   хай-хэт-«тик». Юридически чисто, уникально. Идея под Kozlov Club: «звуки записаны
   в клубе» — это и история, и фишка. Записывай сразу с разной силой удара —
   получишь готовый набор акцент / норма / тихо.
2. **CC0 / Creative Commons** (напр. Freesound.org). Фильтруй по лицензии: CC0 — можно
   всё без указания автора; CC с attribution — читай условия. Слушай и отбирай вручную,
   качество разное. ВАЖНО: проверяй лицензию на странице каждого конкретного файла
   на момент скачивания.
3. **Платные royalty-free сэмпл-паки** с лицензией на встраивание в распространяемый
   софт. Студийное качество, но читай лицензию — должна явно разрешать использование
   внутри приложения.

**Нельзя:** звуки из других метроном-приложений, защищённые сэмплы драм-машин,
коммерческие библиотеки без лицензии. Это риск на App Store review.

### Какой звук подходит метроному

- **Острый транзиент — главное.** Резкая атака в первые миллисекунды: мозг ловит
  «момент доли» именно по атаке. Длинные звуки с медленным нарастанием не годятся —
  теряется точная точка удара. Поэтому классика метронома деревянная (woodblock, clave).
- **Минимум 2-3 тембра одного звука:** акцент (1-я доля, выше/громче), обычная доля,
  сабдивизия (тише/глуше). Лучше, когда это вариации одного источника — звучат как семья.

### Чек-лист по звуку (этап Claude Code)

- [ ] Сэмплы короткие, с мгновенной атакой (острый транзиент).
- [ ] Есть тембры: акцент / норма / тихо (+опционально сабдивизия).
- [ ] У каждого звука подтверждена лицензия на коммерческое встраивание.
- [ ] Звук грузится в AVAudioEngine, планируется сэмпл-точно (НЕ Timer).
- [ ] Вспышка орба в UI совпадает с атакой звука (см. раздел 3, kansei).
- [ ] Несколько наборов тембров на выбор пользователю (вуд-блок / мягкий / цифровой).

Ты — staff iOS-инженер, специалист по SwiftUI и аудио. Создай нативное
iOS-приложение метронома + тюнера на SwiftUI (iOS 17+).

(CoreHaptics) на каждый удар.

Структурируй проект чисто: модель метронома отдельно от вью, используй @Observable,
async/await. Собери через xcodebuild и почини все ошибки сборки.
```

## 6. Чек-лист «мегаудобства» (на что смотреть при тестах)

- [ ] Запуск/стоп — одним тапом по орбу, без поиска кнопки.
- [ ] BPM меняется и жестом, и числом — точно и быстро.
- [ ] Глаз сразу находит главное (BPM, доля) — ничего не перегружено.
- [ ] Удар видно периферийным зрением (свечение), можно не смотреть в экран.
- [ ] Haptic совпадает со звуком — чувствуется кожей.
- [ ] Сложный размер выставляется за 2-3 жеста, не больше.
- [ ] Пресет вызывается одним тапом по memory dot.
- [ ] В покое экран спокойный, не «кричит» контролами.
```
