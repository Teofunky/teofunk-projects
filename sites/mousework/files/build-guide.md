# КАК СОБРАТЬ «КАЛИБРАТОР МЫШИНОЙ ВОЗНИ»
## Пошаговое руководство: от идеи до продукта через Claude Design + Claude Code

> Держи этот документ открытым. Идём строго по этапам. Не перепрыгивай — каждый следующий шаг опирается на артефакт предыдущего.

---

## БОЛЬШАЯ КАРТА (чтобы видеть весь путь)

```
ЭТАП 0  Подготовка файлов и доступов
ЭТАП 1  Claude Design — собрать «лицо» продукта (экраны, дизайн-система)
ЭТАП 2  Handoff — передать дизайн в Claude Code одной кнопкой
ЭТАП 3  Claude Code — построить движок (агенты, провенанс, API)
ЭТАП 4  Сборка фронт + бэк, локальный запуск
ЭТАП 5  Аудит, тесты, защита
ЭТАП 6  Деплой и первые пользователи
```

Логика разделения: **Design рисует то, что видно. Code строит то, что думает.** Наш продукт тяжёлый именно логикой (пайплайн проверки гипотез), поэтому 80% работы — в Code. Design нужен, чтобы Code строил под готовый, утверждённый интерфейс, а не угадывал.

## ЭТАП 0. ПОДГОТОВКА (30–60 минут)

### 0.1 Что собрать в одну папку
Создай на компьютере папку `calibrator/` и положи туда:
- `principles-core.md` — конституция ядра (уже готова, 23 раздела). **Это главный файл проекта.**
- `mousework-calibrator-v3.jsx` — рабочий прототип (доказательство, что концепт живой).
- `build-guide.md` — этот документ.

### 0.2 Какие доступы нужны
- **Claude Pro или Max** — Claude Design в research preview раскатывается на платных подписчиков. Без платного тарифа Design не откроется.
- **Claude Code** — ставится отдельно (приложение/CLI). Для конфиденциального проекта используй Max/Team/Enterprise: на этих тарифах данные не уходят в обучение.
- **GitHub-аккаунт** — пустой репозиторий `calibrator`. Сюда ляжет весь код; Claude Code работает с репозиторием.

### 0.3 Реши заранее два вопроса (от них зависит всё)
1. **Где берём данные пользователя?** На MVP — ручной ввод + загрузка файлов (CSV/текст) + веб-поиск. Коннекторы (почта, календарь) — позже.
2. **Личный сервис или многопользовательский?** На MVP делай **однопользовательский без регистрации** — это в разы проще и быстрее до первого результата. Аккаунты добавишь потом.

> ⚠️ Главное правило этапа 0: **не начинай строить, пока не перечитал `principles-core.md`.** И Design, и Code будут опираться на него. Если в нём что-то кажется лишним — вычеркни сейчас, на бумаге это бесплатно.

## ЭТАП 1. CLAUDE DESIGN — «ЛИЦО» ПРОДУКТА

Цель этапа: получить визуальный прототип всех экранов и дизайн-систему (цвета, шрифты, компоненты), которую потом прочитает Claude Code.

### 1.1 Что загрузить в Claude Design
При старте загрузи / вставь:
- `principles-core.md` — чтобы Design понимал суть и термины (бейджи, оптики, паспорт вывода).
- `mousework-calibrator-v3.jsx` — как референс внешнего вида (тёмная «приборная» эстетика). Можно использовать веб-капчур: указать Design на запущенный прототип, и он вытянет цвета и типографику.

### 1.2 Первый промпт для Claude Design
Скопируй целиком:

```
Я строю аналитический сервис «Калибратор мышиной возни» — Pattern
Intelligence платформу. Прилагаю конституцию ядра (principles-core.md)
и рабочий прототип внешнего вида (.jsx).

Эстетика: тёмная «приборная», как осциллограф — монопространственный
шрифт, сканлайны, акцент бирюзовый (#4ec9b0), фон почти чёрный
зелёно-графитовый. Никакого «AI-слопа», без фиолетовых градиентов.

Собери дизайн-систему по этому прототипу, затем спроектируй экраны
(список ниже). Каждый экран — отдельная страница прототипа.
```

### 1.3 Экраны, которые нужно попросить (по одному за раз)
Проси Design делать их последовательно, проверяя каждый:

1. **Главный экран / «Поток хаоса»** — поле ввода событий, загрузка файла, выбор оптики (12 линз), переключатель «Связать с миром», большая кнопка «Откалибровать возню».
2. **Экран результата — вкладки:**
   - Локальное ✕ Мировое (твой сигнал против контекста);
   - Пульс внимания (всплеск/растёт/ровно/гаснет);
   - Паттерны и гипотезы;
   - Что я не вижу (слепые зоны);
   - Что делать.
3. **Экран «Шум / Мусор / Сигнал / Ядро»** — счётчики классификации входа (из §14 конституции): «Из 1240 событий: 812 шум, 276 мусор, 119 сигналы, 33 ядро».
4. **Карточка гипотезы с протоколом опровержения** (§9–10): «за / против / альтернативы / что проверит / что опровергнет», бейдж доказанности, кнопка «Разбей красивую гипотезу» (адвокат дьявола).
5. **Паспорт вывода** (§11) — раскрывающаяся панель: источники, период, что исключено, метод, слабое место, что изменит вывод.
6. **Слои масштаба** (§15) — микро → мезо → макро → мета → мир.
7. **Панель шести кнопок:** Покажи скрытый порядок · Что я не вижу · Разбей красивую гипотезу · Покажи альтернативы · Что проверить первым · Снизь фантазию до нуля.
8. **Красные флаги ложного смысла** (§20) — предупреждающая плашка.

### 1.4 Как доводить дизайн
Используй инструменты Design: правки через чат, инлайн-комментарии, слайдеры. На каждом экране спрашивай себя: *виден ли здесь бейдж доказанности? видно ли, что можно опровергнуть вывод?* Если нет — проси добавить. Эпистемология должна быть **видимой**, а не спрятанной.

### 1.5 Выход этапа 1
- Дизайн-система (цвета/шрифты/компоненты) — сохранена.
- 8 экранов-прототипов готовы и одобрены тобой.
- Внутреннее ощущение: «да, я бы этим пользовался».

> 💡 Не уходи в Code, пока экраны не устаканились. Переделать дизайн в Design дёшево; переделывать код — дорого.

## ЭТАП 2. HANDOFF — ПЕРЕДАЧА В CLAUDE CODE

Claude Design умеет паковать готовый дизайн в handoff-бандл и передавать в Claude Code одной инструкцией.

### 2.1 Что сделать
1. В Claude Design нажми экспорт → handoff в Claude Code (либо экспортируй HTML/CSS-бандл).
2. Этот бандл содержит дизайн-систему и разметку экранов — Claude Code будет строить, уважая эти цвета, шрифты и компоненты, а не выдумывать свои.

### 2.2 Что положить рядом с бандлом
В репозиторий `calibrator/` (или прямо в контекст Claude Code) добавь `principles-core.md`. **Дизайн говорит Code, как выглядеть. Конституция говорит Code, как себя вести.** Нужны оба.

## ЭТАП 3. CLAUDE CODE — ДВИЖОК (ядро работы)

Здесь строится то, что делает продукт продуктом. Идём подсистемами; каждую проси у Claude Code отдельной задачей и проверяй, прежде чем двигаться дальше.

### 3.1 Первый промпт для Claude Code
```
Это проект «Калибратор мышиной возни» — Pattern Intelligence платформа.
Прилагаю: (1) handoff-бандл дизайна из Claude Design, (2) конституцию
ядра principles-core.md — это спецификация ПОВЕДЕНИЯ, обязательная.

Стек: фронт — React по дизайн-бандлу; бэк — Python + FastAPI; модель —
через Anthropic API. Начни с архитектуры репозитория и пустого скелета
(фронт + бэк + общие типы), без бизнес-логики. Покажи структуру папок и
объясни, куда что ляжет. Потом по моей команде будем наполнять
подсистемы по одной.
```

### 3.2 Подсистемы — строить строго в этом порядке
Порядок важен: каждая опирается на предыдущую.

**Шаг A. Приём и нормализация входа.**
Загрузка CSV/текста + ручной ввод. Каждое событие приводится к единому виду: субъект, действие, время, источник, домен, достоверность (§3 конституции).

**Шаг B. Классификатор шум/мусор/сигнал/ядро (§14).**
Отделяет важное от неважного. Отброшенное НЕ удаляется — хранится для аудита.

**Шаг C. Base rate + сезонность (§12–13).**
Прежде чем называть что-то аномалией — сравнение с базовой нормой. Проверка календарных ловушек. Без этого — пометка «норма неизвестна».

**Шаг D. Поиск паттернов и связей.**
Повторы, лаги, кластеры, «перед X обычно Y». Строится граф связей.

**Шаг E. Многоагентный пайплайн гипотез — сердце продукта.**
Три прохода (по §9, §10, §16):
1. *Генератор* — формулирует гипотезы.
2. *Адвокат дьявола* — пытается каждую разрушить (ошибка выборки, сезонность, совпадение, смена источника, конспирология).
3. *Калибратор доказанности* — проставляет бейдж, понижает при сомнении, добавляет «что опровергнет» и минимум 2 альтернативы.

**Шаг F. Слой мира + пульс внимания (§6).**
Веб-поиск (через Anthropic API tool) по сущностям: что уже случилось + что человечество ищет сейчас. Блок проектируется совместимым с Google Trends API — реальные ряды встанут на готовое место, когда он выйдет из alpha.

**Шаг G. Паспорт происхождения (§11).**
Каждый вывод сопровождается провенансом (по духу W3C PROV: сущности → действия → агенты). Вывод без паспорта система не отдаёт.

**Шаг H. Формула силы сигнала + ранжирование (§17).**
Наверх поднимается не самый яркий, а лучше всех выдержавший проверку сигнал.

**Шаг I. API между фронтом и бэком.**
Один эндпоинт `POST /calibrate` принимает поток + оптику + флаг «связать с миром», возвращает JSON всех вкладок. Фронт из дизайн-бандла подключается к нему.

### 3.3 Как работать с Claude Code эффективно
- Одна подсистема = одна задача. Не проси всё сразу.
- После каждой — проси запустить и показать результат, прежде чем идти дальше.
- Держи `principles-core.md` в контексте — ссылайся на номера разделов: «реализуй §12 base rate».
- Проси писать тесты сразу с кодом, а не потом.

## ЭТАП 4. СБОРКА И ЛОКАЛЬНЫЙ ЗАПУСК

1. Попроси Claude Code собрать всё вместе: фронт обращается к бэку, бэк к API.
2. Запусти локально. Прогон на дефолтном примере (бизнес-кейс из прототипа).
3. Проверь по чек-листу качества (ниже). Если вкладка пустая или бейдж не проставлен — это баг поведения, не косметика; чини сразу.

## ЭТАП 5. АУДИТ, ТЕСТЫ, ЗАЩИТА

Код из AI-инструментов работает, но не production-ready как есть — его надо проверить по стандартным осям.

Проси Claude Code пройтись по каждой:
- **Безопасность** — ключ API только на бэке, никогда во фронте; защита от инъекций в загружаемых файлах.
- **Приватность** — реализуй «Права пользователя» (§22): удалить/понизить источник, увидеть отброшенное, очистить память анализа.
- **Тесты** — покрыть пайплайн гипотез: подаём данные с известной сезонностью → адвокат дьявола обязан её поймать и не пустить бейдж выше ГИПОТЕЗА.
- **Анти-конспирология (§18)** — тест: подаём 2 совпадения без механизма → система обязана выдать СПЕКУЛЯЦИЮ, а не ПРИЧИНУ.
- **Доступность и нагрузка** — базовая проверка.

## ЭТАП 6. ДЕПЛОЙ И ПЕРВЫЕ ПОЛЬЗОВАТЕЛИ

1. Попроси Claude Code подготовить деплой (фронт на статик-хостинг, бэк на облачный сервис; переменные окружения для ключей).
2. Запусти на себе 1–2 недели на реальных данных. Веди список: где система нашла настоящее, где выдала красивую ерунду. Каждая «ерунда» = задача ужесточить соответствующий §-модуль.
3. Дай 3–5 людям из разных оптик (бизнес / врач / исследователь). Их реакция покажет, какая линза «продаёт» продукт.
4. Только после этого — аккаунты, многопользовательскость, коннекторы, живой пульс внимания во времени.

## ЧЕК-ЛИСТ КАЧЕСТВА (сверяться на этапах 4–6)

Хороший ответ системы:
- [ ] называет, что **на самом деле** происходит, а не пересказывает ввод;
- [ ] показывает связи, которые человек сам не свёл бы;
- [ ] у каждого вывода есть бейдж доказанности;
- [ ] у каждой гипотезы есть «что опровергнет» и ≥2 альтернативы;
- [ ] аномалия объявлена только после сравнения с base rate;
- [ ] сезонность проверена перед бейджем ПАТТЕРН;
- [ ] у каждого вывода есть паспорт происхождения;
- [ ] эффектная связь понижена анти-конспирологическим фильтром;
- [ ] ни одной выдуманной детали, источника или цифры;
- [ ] оптика меняет приоритеты, но не факты.

## ЧТО НЕ ДЕЛАТЬ (частые ошибки)

- ❌ Строить «весь мир» сразу. MVP = «загрузил хаос → получил карту». Один сценарий, доведённый до конца.
- ❌ Уходить в Code до того, как дизайн устаканился.
- ❌ Делать аккаунты и коннекторы до первого работающего результата.
- ❌ Гнаться за «умностью» вместо дисциплины. Сила продукта — в §9–21, не в красивых формулировках.
- ❌ Принимать код как готовый без аудита (этап 5).

## КОРОТКО, ОДНОЙ ФРАЗОЙ НА КАЖДЫЙ ИНСТРУМЕНТ

- **`principles-core.md`** — мозг. Решает, как система думает и где молчит.
- **Claude Design** — лицо. Превращает мозг в экраны, отдаёт дизайн-систему.
- **Claude Code** — тело. Строит движок под лицо и по правилам мозга.
- **Ты** — совесть продукта. На каждом шаге спрашиваешь: «это найденная истина или красивая ерунда?»
