# KOZLOV CLUB — компактный календарь концертов

Интерактивный UI/UX-прототип от 4 ноября 2026 года. Открыть `index.html` в браузере. Файл автономный, без сборки, библиотек и сетевых запросов.

## Цель

Сделать выбор даты и переход к концертам быстрым на мобильных устройствах и компактным на десктопе. Прототип демонстрирует нижнюю панель на телефоне и модальное окно шириной 440 CSS px на компьютере.

## Что реализовано

- Один месяц, недели с понедельника, переключение месяцев.
- «Сегодня», «Завтра», «Выходные», «7 дней» — без переноса кнопок на вторую строку при типовой ширине телефона.
- Разделение режимов **«День» / «Период»**: одиночный выбор по одному нажатию или выбор начала и конца диапазона двумя нажатиями.
- Подсветка сегодняшнего числа, выбранного числа и диапазона (начала/конца и промежуточных дат).
- Недоступность прошедших дат, сброс, динамическая подпись выбора и кнопка «Показать N концертов».
- Клавиатурная навигация стрелками, Home/End, PageUp/PageDown, закрытие по Esc, базовый фокус внутри диалога, `aria-label` с полными датами, адаптивность.
- Применение фильтра в демо закрывает панель и изменяет заголовок списка. Реальные мероприятия не загружаются.

## Важно: демонстрационные данные

Дата «сегодня» зафиксирована на **04.11.2026**, чтобы прототип можно было визуально сравнить со скриншотами. На 4 ноября использовано число **7 концертов**, видимое на предоставленном скриншоте. Количество для остальных дат **условное, алгоритмически сгенерировано**. Три карточки афиши снизу — макеты без реальных артистов и событий. На реальном сайте это заменить.

## Техническое задание на интеграцию в WordPress

1. Выделить календарь в самостоятельный компонент (стили под пространством имён вроде `.kc-calendar`), не переносить глобальные CSS-правила демо непосредственно в боевую тему.
2. Источник доступных дат и чисел концертов — текущая система афиши / event API WordPress. Подсчёт учитывать реально доступные для показа мероприятия, их отмену, дубли и расписание на четырёх сценах. Продажа билетов и «есть концерты» — разные состояния, не смешивать.
3. «Сегодня» вычислять на сервере/клиенте в согласованной временной зоне **Europe/Moscow**. Формат передачи в фильтр — локальная календарная дата `YYYY-MM-DD`, а не UTC timestamp; конец периода включительный.
4. При выборе отдельного дня передавать `date=YYYY-MM-DD`; для диапазона — `start_date` и `end_date` с документированными именами параметров, совместимыми с реальным маршрутом/плагином афиши. Эти имена здесь — **пример контракта, не утверждение о текущем API**.
5. Кнопка «Показать» должна отфильтровать **реальную** программу без сюрпризов: в пределах периода, по всем четырём сценам, с корректным счётчиком и обработкой нулевого результата.
6. Проверить сценарии: день с 0 концертами; одно событие; число больше 9; аншлаг; отмена; переход между месяцами/годами; диапазон через границу месяца; смена режима; возврат фокуса; повторное открытие.
7. Проверить в Safari iOS, Chrome Android, браузерах на 320/375/390/430 CSS px, desktop; с экранной клавиатурой, VoiceOver/NVDA, масштабом 200%.
8. Проверить доступность WCAG 2.2 AA: контраст, размеры зон нажатия, скринридер, управление с клавиатуры, ловушка/возврат фокуса и анонсы.
9. Настроить кеширование статистики количества концертов и инвалидацию при публикации, отмене и изменении события.
10. Запустить A/B-тест действующего и нового календаря: доля пользователей, открывших календарь; выбравших дату; увидевших список; перешедших к карточке концерта; начавших покупку. Без этих данных улучшение конверсии не доказано.
