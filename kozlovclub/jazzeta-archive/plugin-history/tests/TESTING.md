# Воспроизведение локальных тестов

Только отдельная одноразовая установка WordPress и пустая тестовая БД. **integration.php очищает все таблицы es_*; advanced.php создаёт записи WordPress, меняет настройки и моделирует отказ таблицы аудита; safety-browser.cjs временно записывает синтаксическую ошибку в модуль и исключение в шаблон, меняет режимы и выполняет настоящую деактивацию/активацию.** Не запускайте на действующем сайте или копии с ценными редакционными данными. Предпочтительно изолированный контейнер/виртуальная машина.

Проверены WordPress 6.4 и 7.1.3, PHP 8.3.6, MariaDB 10.11.7, Chromium 156.0.8078.47. Runtime, базы данных, браузер и зависимости не включены в ZIP. Тестовые новости синтетические; их источники не подтверждают реальных фактов.

## Окружение

1. Разверните свежий single-site WordPress с отдельным MySQL/MariaDB InnoDB. Установите плагин из пакета.
2. URL: `http://127.0.0.1:18080`. Для браузерного набора требуется этот host (порт можно сменить через переменную). Web-сервер должен обслуживать обычные WordPress rewrites и REST.
3. Первый пользователь, ID **1**, должен быть администратором: логин `es_owner`, пароль `local-editor-test-pass`. Эти открытые тестовые реквизиты нельзя использовать вне изолированного окружения. Выберите его владельцем в настройках газеты.
4. В wp-config.php: `WP_ENVIRONMENT_TYPE='local'`, `DISABLE_WP_CRON=true`, `WP_HTTP_BLOCK_EXTERNAL=true`; `WP_DEBUG=true`, `WP_DEBUG_LOG=true`, `WP_DEBUG_DISPLAY=false`. Закройте индексацию. Постоянные ссылки: `/%postname%/`; часовой пояс Europe/Moscow. Другие плагины отключены.
5. PHP CLI и web PHP должны читать одну БД и поддерживать mysqli, mbstring, json, dom, xml, ctype, tokenizer, fileinfo, iconv. Для проверки гонок нужен разрешённый `proc_open`.
6. Установите Node.js, пакет Playwright и совместимый Chromium в окружение тестирования. При внешней установке задайте NODE_PATH. ES_TEST_CHROME — необязательный абсолютный путь к браузеру.
7. Fixtures используют даты октября 2026. Если запускаете до этих дат, проверки будущих источников ожидаемо заблокируют публикацию. Не отключайте такие проверки в рабочем плагине.

## Запуск

Пример после запуска локальных web/DB процессов (замените пути):

```bash
export ES_TEST_ALLOW_RESET=1
export ES_TEST_ROOT=/absolute/disposable-workdir
export ES_TEST_BOOTSTRAP=/absolute/wordpress/wp-load.php
export ES_TEST_PHP=/absolute/path/to/php
export ES_TEST_BASE_URL=http://127.0.0.1:18080
export ES_TEST_OUTPUT=/absolute/disposable-workdir/results
bash /absolute/plugin/tests/run-local.sh
```

Последовательность обязательна: `integration.php` (51 проверка) → `browser.cjs` (46) → `audit-browser.cjs` (24) → `safety-browser.cjs` (64) → `advanced.php` (39). Следующий прогон начинается снова с integration. Последний набор зависит от реально опубликованного через браузер первого номера. `run-local.sh` удаляет временный файл с тестовым Application Password при завершении. Снимки браузера остаются локально для визуального контроля; они не входят в релиз.

Ожидаемый итог: пять строк TOTAL (51, 46, 24, 64, 39), всего 224, код выхода 0. Проверка отказа намеренно временно переименовывает таблицу revisions; соответствующая запись ошибки БД в debug.log ожидаема. Это не повод игнорировать другие PHP/SQL ошибки.

Проверка PHP-синтаксиса: `find /absolute/plugin -name '*.php' -exec php -l {} \;`. JavaScript: `node --check assets/admin.js`, `node --check assets/newspaper.js`, `node --check tests/browser.cjs` из папки плагина. Эти проверки не доказывают совместимость конкретной темы.

## Что измеряется

В advanced создаются 1200 синтетических строк архива, затем измеряется вызов Repository::listing(2,true) с холодным и прогретым transient. EXPLAIN должен выбрать public_archive. Нагрузочные строки удаляются после проверки. Это микроизмерение метода в локальной БД, без сети, HTML-рендера и реального конкурентного трафика. Не использовать как обещание времени ответа сайта.

Дополнительный audit-browser.cjs проверяет короткие URL/301, canonical/JSON-LD/архив/sitemap, plain permalink fallback, отсутствие интеграционных hook в предпросмотре, четыре варианта бренда и логотип на 320/390 px. Он временно создаёт собственный MU-файл с безвредными маркерами и синтетическое вложение медиатеки, затем удаляет их и восстанавливает настройки. Проверка синтаксиса JS включает также tests/audit-browser.cjs.

## Отказы и закрытый запуск

safety-browser.cjs требует чистую одноразовую среду и права записи в файлы тестового плагина. Он проверяет доступ разных ролей, обычные/старые/query URL и REST, отдельное открытие public, остановку, аварийный файл и константу, модульный ParseError и исключение в шаблоне, восстановление closed и неизменность снимков всех редакционных таблиц, существующих записей и настроек темы. Контрольная проверка админки использует plugins.php: Dashboard на WordPress 6.4 сам создаёт quick-draft, что не является изменением со стороны газеты.

Нормальное завершение восстанавливает подменённые файлы в finally, удаляет собственные MU-маркеры и временных пользователей. После аварийного завершения самого теста проверьте целостность файлов по исходному ZIP; безопаснее заново создать одноразовую среду. Если остались собственные es-newspaper-audit-fixture.php / es-safety-fixture.php, новый тест откажется их перезаписывать: используйте чистую установку. Не запускайте два набора одновременно на одной БД/папке.

Ожидаемые fault-записи: ParseError class-validation.php, RuntimeException newspaper.php и ошибки БД при переименованной таблице revisions. Не отключайте защиту или обработку ошибок ради прохождения тестов. Проверка fatal shutdown при исчерпании памяти и повреждения главного загрузчика не моделировалась; не выдавайте тесты Throwable за проверку всех возможных сбоев.

При тесте файл DISABLE-GAZETA не должен существовать заранее; в релиз включён только .example. Временные Application Password и все пароли фикстур предназначены исключительно для localhost. После теста уничтожьте среду. JS-синтаксис проверяется также для tests/audit-browser.cjs и tests/safety-browser.cjs.
