# Отчёт проверки 0.3.2

Дата: 21 октября 2026. Статус: пакет подготовлен для приёмки на тестовой копии сайта. Это не подтверждение готовности действующего kozlovclub.ru к установке. На действующем сайте ничего не устанавливалось; Beget не подключался.

224 проверяемых утверждения, повторённых на двух версиях WordPress: 448 успешных проверок. Промежуточные отладочные прогоны не включены. Браузер Chromium 156.0.8078.47 через Playwright; реальные локальные WordPress и MariaDB, без функций-заглушек. Нативный синтаксический контроль: 18 PHP-файлов, 5 JavaScript/CJS, shell run-local.sh. Проверки не воспроизводят конфигурацию рабочего сайта.

## Проверено

- Схемы 1.0/1.1, ограничение размера, неправильные даты/типы/поля, повторные ID, неизвестные ссылки фактов, небезопасные URL, XSS, абзацы и форматирование.
- Три уровня подтверждения, обязательная проверка источников, независимые цепочки, атрибуция единственного источника и человеческое подтверждение всех статей.
- Изолированные права автора/редактора/импортёра/владельца. Другой администратор не заменяет выбранного владельца. Application Password импортёра не даёт создавать обычные записи.
- Анонимный импорт запрещён; маршрута публикации REST нет; nonce, cookie и отдельный checkbox обязательны. Прямой вызов публикации без разрешения административного обработчика отклоняется.
- Повторный импорт, конфликт import_id, обязательный If-Match, устаревшие формы, защита ручных правок и опубликованных данных. **16 одновременно запущенных процессов импорта** получают один ID выпуска.
- Два параллельных ручных обработчика публикации дают разные последовательные номера. Отказ журнала аудита откатывает публикацию вместе с номером; ошибка импорта не оставляет производные события.
- Совпадения URL с tracking-параметрами, publication_id, content_hash, event_id, полных текстов по всему опубликованному архиву. Повторы URL/ID/хешей внутри статьи/выпуска. Явная связь существенного развития с прошлой новостью.
- Настоящие браузерные действия: вход, редактор WordPress, защищённый предпросмотр, утверждение, редактирование опубликованной статьи без изменения читательского снимка, снятие и повторное утверждение с сохранением номера.
- Мобильные размеры 320/390 px, планшет 768 px, компьютер 1440 px: горизонтального переполнения нет. Визуально просмотрены классическая полоса, мобильная полоса и PNG. Ночной режим, PNG 1080×1350, чтение без JavaScript.
- Смена названия через WordPress обновляет SEO title и не меняет материал/canonical. Проверены JSON-LD, публичная API-проекция, noindex/no-store предпросмотра, sitemap и 404 для несуществующих страниц/снятых материалов. Приватные заметки не выводятся.
- Ручной перенос старого номера оставляет исходную запись неизменной и создаёт только черновик; повторное копирование идемпотентно. История восстанавливает рабочую версию и снимает подтверждения. Деактивация/реактивация сохраняют данные.
- Обычные записи WordPress до и после сценария импорта идентичны.

## Найдено и исправлено до упаковки 0.3.0

1. Небольшое переполнение шапки на 320 px.
2. Неверный порядок регистрации подменю оформления в WordPress.
3. Недостающий резервный serif-шрифт в canvas-карточке.
4. Редкая взаимная блокировка двух импортов: INSERT IGNORE перед FOR UPDATE создавал конкурирующее повышение блокировок. Теперь служебная строка создаётся при активации, а операции сразу берут исключительную блокировку существующей строки. Повторная проверка — 16 конкурентных импортов.
5. Усилены точные проверки внешних ID и хешей публикаций внутри одного выпуска и одной статьи.

## Дополнительные исправления и проверки 0.3.1

- Короткий URL номера /gazeta/YYYY-MM-DD/ и 301 со старого /issue/. Проверены canonical, JSON-LD, sitemap, архив и plain permalink fallback. Непубликуемые и невозможные даты возвращают 404.
- Публичные es_newspaper_head/es_newspaper_footer проверены безопасными тестовыми маркерами; в предпросмотре они не выполняются, wp_head темы не вызывается. Реальный счётчик не подключён.
- Четыре варианта названия (включая одно слово из 80 широких символов), длинные подзаголовок/девиз, PNG и логотип 1200×240 проверены на 320/390 px. Внешний вид тестовой карточки просмотрен.
- Результаты 0.3.0 и 0.3.1 сохранены в history-0.3.0 и history-0.3.1; её независимый аудит сам не воспроизводил наш интеграционный набор. Здесь приведены результаты нового собственного прогона.

## Добавлено и проверено в 0.3.2

- Новая активация closed; ручное утверждение выпуска оставляет анонимный доступ закрытым. Публичное открытие — отдельная форма владельца с сессией/nonce/флажком. Подделка формы, отсутствие согласия, обычный редактор и другой администратор не открывают public.
- Анонимные обычные/старые/query URL, HEAD, sitemap, robots, REST pretty/query; отдельные аккаунты редактора, автора, импортёра и подписчика. Закрытый HTML: no-store, Vary Cookie, noindex, no-referrer, без публичных SEO/hook; карточки в draft-режиме. Импорт с отдельным Application Password работает в closed, но не даёт чтение.
- Обычная главная не загружает редакционные модули: это проверено диагностическим MU-header с положительным контролем на газете. Обычный WordPress REST API продолжает отвечать.
- Пауза запрещает чтение владельцу, API-импорт и запись в репозиторий. Режимы не меняют существующие данные, историю, тему или выбранного владельца.
- При намеренно испорченном модуле аварийный файл оставляет админку доступной и не загружает модули. Константа отключает даже Runtime; снятие флага сохраняет paused.
- Модульный ParseError перехвачен, записана автопауза, работает экран восстановления. Возобновление с испорченным модулем отвергается; после исправления возвращается closed.
- Исключение шаблона удаляет собственный частичный вывод и возвращает общий 503 без текста исключения. Снимки данных сохранены. Реальная деактивация/активация через WordPress API сохраняет данные и возвращает closed даже из public.
- Неизвестное значение режима трактуется как closed. Главная остаётся доступной во время паузы, ошибки модуля и деактивации.

При отладке теста WordPress 6.4 его Dashboard штатно создавал quick-draft, меняя контрольный снимок wp_posts. Для проверки доступности админки используется plugins.php: проверки сохранности данных не ослаблялись. После прерывания тестовой среды требовалась очистка оставшихся собственных MU-фикстур. Это не ошибки редакционной модели.

## Производительность

Синтетический архив: 1203 опубликованные строки, по 12 номеров на страницу. EXPLAIN выбирает индекс public_archive. В прогоне WordPress 6.4 чтение второй страницы заняло около 3 мс без transient и 0,13 мс с ним. Это единичное локальное измерение метода Repository::listing, а не время ответа сайта и не нагрузочный SLA. Число полных JSON-документов, загружаемых архивом, не растёт вместе с архивом: список выбирает только краткие столбцы.

## Границы проверки

- Closed не защищает прямые URL медиатеки. Кэш/CDN, отвечающий до WordPress, требует внешнего исключения и очистки; этот уровень здесь не испытан.
- Автоостановка проверена для ошибок подключения модуля и рендера, но не для всех OOM/fatal, недоступности БД или повреждения главного файла. Проверка синтаксиса и 448 утверждений не являются сертификатом безопасности.
- Настоящая тема, афиша, билетная система, SEO-плагины, Redis/Memcached, Nginx/CDN и настройки хостинга клуба не предоставлены; совместимость проверяется по STAGING-CHECKLIST.md.
- PHP 7.4 заявлен как минимальная целевая версия, но нативные прогоны выполнены на PHP 8.3.6. MySQL 8 отдельно не запускался; испытана MariaDB/InnoDB. Multisite намеренно блокируется при активации.
- Safari/iOS и Firefox отдельно не запускались. Автоматическая проверка ширины не заменяет просмотр реальных материалов на телефонах и проверку доступности человеком.
- Не выполнялись внешнее сканирование уязвимостей, пентест, большие распределённые нагрузочные испытания и проверка истинности новостей. Фикстуры явно синтетические.
- Семантические дубли, перефразирование/перевод, правдивость заявленных цепочек источников и значимость нового факта требуют редакторской проверки; ИИ не подключён.
- В журналах среды были ожидаемые ошибки БД во время моделирования отказа аудита и ошибки заблокированных внешних проверок обновлений WordPress, а также намеренные ParseError/RuntimeException из испытания остановки. Ошибка блокировки из пункта выше исправлена; финальный прогон завершился успешно.
