# Закрытый пилот и аварийное отключение — 0.3.2

Пакет подготовлен локально. На действующем сайте ничего не установлено, его тема, кэш, афиша и билетная система не проверены. Сначала выполните STAGING-CHECKLIST.md на копии с настоящим окружением, затем можно провести ограниченный редакционный пилот на рабочем WordPress. Автотесты из tests/ предназначены только для отдельной пустой локальной БД: они стирают свои таблицы и намеренно повреждают PHP-файлы.

## Что означает закрытый режим

| Режим | Чтение газеты | Редакция и импорт | Переход |
|---|---|---|---|
| closed, по умолчанию | Только es_edit, включая администратора | Доступны в пределах отдельных прав | Выбранный владелец отдельно открывает public |
| public | Все посетители: только утверждённые снимки | Рабочие правки не меняют снимок без утверждения | Владелец/администратор может закрыть или остановить |
| paused | Никто, включая редакцию | Операции изменения/импорта заблокированы | Администратор/владелец возвращает closed |

Выдавайте редакторам отдельную роль «Газета — редактор», импортёру — «Газета — импортёр». Обычные роли WordPress «Редактор», «Автор», «Подписчик» не получают доступ автоматически. Публикация выпуска и открытие газеты — разные действия. Публичное открытие показывает **все** утверждённые выпуски, поэтому сначала снимите тестовые номера.

Проверка действует для выпусков, материалов, подшивки, предпросмотра, прежних адресов с /issue/, query URL и собственного API. Закрытая газета не объявляется в robots, её sitemap недоступен. HTML для редакции отправляет private/no-store/noindex/Vary Cookie и не вызывает публичные точки интеграции. По одному nonce или скрытой ссылке доступ получить нельзя: нужна авторизованная учётная запись с правом es_edit. PNG закрытого просмотра помечен черновиком, дайджест не содержит ссылок для распространения. Копирование текста авторизованным редактором технически не запрещается.

Медиатека WordPress не является закрытым хранилищем: прямой URL картинки остаётся публичным. В пилоте используйте только открытые или неконфиденциальные медиа. Настоящее закрытое хранилище вложений потребует отдельной реализации.

## До установки на рабочий сайт

1. Получите проверяемую резервную копию файлов и всей БД, с понятным способом восстановления через хостинг. Проверьте восстановление на копии. Запишите текущие версии и контрольное состояние главной, афиши, покупки билета, меню и темы. Имеющиеся продажи/заказы нельзя откатывать старой полной БД без согласования последующих изменений: сначала отключайте только плагин.
2. Проверьте доступ к файловому менеджеру/SFTP без WordPress и возможность переименовать ровно одну папку. Сохраните прежний ZIP плагина. Не передавайте пароли в документах проекта.
3. Используйте поддерживаемые ветки WordPress/PHP и исправления безопасности. Минимум PHP 7.4 в заголовке — техническая совместимость, а не рекомендация эксплуатировать устаревшую ветку. Точная версия сервера клуба требует отдельной проверки. Приёмочные тесты не повод одновременно обновлять весь рабочий сайт.
4. Настройте исключения HTML-кэша на каждом уровне: CDN, reverse proxy/Nginx, WordPress cache plugin, service worker, если есть. Исключите `/gazeta` и `/gazeta/*`, `/wp-json/ezhednevny-standard/v1/*` (или фактический REST prefix), любые запросы с `es_view` и `rest_route=/ezhednevny-standard/v1/...`. Для WordPress в подпапке добавьте её к путям. Исключения должны действовать до загрузки PHP. CSS/JS кэшировать можно.
5. Очистите прежние ответы этих адресов, включая query URL и прежние редиректы. Убедитесь снаружи, что ответ редактору не попадает анонимному посетителю. Не полагайтесь только на статус HIT/MISS: проверьте тело, статус и заголовки из двух независимых сессий, сначала после редактора, затем в обратном порядке.
6. Проверьте HTTPS, индивидуальные аккаунты и действующую защиту входа. Импортёр имеет только es_import, использует отдельный отзываемый Application Password; пароль владельца ему не выдаётся. Beget остаётся отключённым. Никаких новых security/cache плагинов этот пакет автоматически не устанавливает.
7. Выберите небольшое окно работ; сохраните журналы PHP/БД и наблюдайте нагрузку и ошибки. Не включайте display_errors посетителям и не публикуйте журнал с приватными данными. Изменения касаются только собственного кода/таблиц и штатных опций/ролей/rewrite WordPress. Меню «Газета» не добавляется.

## Ограниченная проверка на рабочем WordPress

После отдельного согласования загрузите пакет, активируйте под владельцем, проверьте «Режим и остановка»: closed. Проверьте ID владельца в «Доступе». Предоставьте es_edit только участвующим редакторам. Сначала один неконфиденциальный тестовый выпуск. Не открывайте public.

Проверьте редактирование, источники, абзацы, предупреждения дублей, предпросмотр, ручное утверждение и закрытое чтение. Затем анонимный просмотр прямых/старых/query адресов, API и sitemap: материалы недоступны. Повторите после входа редактора и через внешний CDN. Сравните главную, афишу, билетный сценарий, меню и журналы с исходным состоянием. Попробуйте паузу и возврат closed. При появлении ошибок, ухудшении ответа основного сайта или утечке через кэш остановите пилот, очистите кэш газеты и используйте процедуру ниже.

Запишите результат, окружение, обнаруженные дефекты и решение владельца. Открытие посетителям, индексация, пункт меню, аналитика и Beget — последующие самостоятельные действия.

## Три способа остановки

**Админка работает.** «Газета → Режим и остановка → Остановить газету». Чтение и импорт недоступны; материалы остаются в БД. Для полного отключения — штатная деактивация только этого плагина. При ней сохраняются данные и устанавливается closed для следующей активации. Не удаляйте таблицы и не восстанавливайте всю БД без необходимости.

**Модули газеты мешают работе.** В файловом менеджере создайте пустой `wp-content/plugins/kozlov-jazzeta/DISABLE-GAZETA`, без расширения. В комплекте только образец `DISABLE-GAZETA.example`: он сам ничего не отключает. Флаг проверяется до подключения модулей. При обработанном запросе он записывает paused; удаление флага не открывает газету публике. Альтернатива для специалиста — `define('KOZLOV_GAZETA_DISABLED', true);` в wp-config.php до подключения wp-settings.php; при существующей константе измените её значение, не определяйте повторно. Флаг внутри папки может исчезнуть при замене ZIP; до обновления зафиксируйте паузу и резервную копию.

**Не работает сама загрузка PHP/WordPress.** Через хостинг переименуйте только `wp-content/plugins/kozlov-jazzeta` в `kozlov-jazzeta.off`. Это внешний способ убрать код из следующего запроса. Не переименовывайте целиком plugins, не отключайте афишу/платежи. Очистите кэш газеты, проверьте главную/афишу/билеты. Переименование не меняет данные и само по себе не обновляет сохранённый режим: возвращая папку, сначала положите в неё DISABLE-GAZETA, выполните запрос, затем после исправления снимите флаг и верните closed через панель. Проверьте статус плагина в WordPress: ядро могло его деактивировать. При выключенном плагине старый шорткод [kozlov_jazzeta] может отображаться текстом — удалите его вручную, не переписывая страницы автоматически.

## Что делает автоматическая остановка и чего она не гарантирует

Runtime загружает репозиторий/импорт/шаблоны только на собственных запросах, в административной части и CLI. Обычная главная и афиша обходятся без редакционных модулей. Ошибка подключения модуля перехватывается, газета переводится в paused. Ошибка рендера отбрасывает собственный буфер и отдаёт общий ответ 503 без текста исключения; модульная ошибка оставляет отдельный экран восстановления. Журнал состояния хранит время, тип, имя файла и строку; после исправления и явного согласия проверяется загрузка и разрешается только closed. Это проверка загрузки, а не полный самотест всех сценариев.

Shutdown-handler пытается отметить собственную фатальную ошибку, но память, процесс PHP, БД и сервер общие с WordPress. Абсолютной гарантии «плагин не может уронить сайт» нет. Повреждение главного PHP-файла до исполнения, некоторые OOM, авария БД, ошибки других плагинов, остановка процесса и закэшированный до PHP ответ требуют внешнего вмешательства. WordPress Recovery Mode может помочь при некоторых фатальных ошибках, но не заменяет доступ к файлам и резервную копию.

Закрытый режим — ограничение доступа к газете, не песочница для PHP и не сертификация соответствия всем нормам безопасности. Допуск на рабочий сайт зависит от его реального окружения и результатов приёмки. Полноценный внешний пентест и аудит инфраструктуры в эту проверку не входили.
