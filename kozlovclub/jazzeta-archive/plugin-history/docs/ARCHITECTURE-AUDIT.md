# Архитектурный аудит и решение 0.3.0

21 октября 2026. Исходники: приложенный ZIP 0.2.0, редакционный пакет v1 и HTML-макет; доступные сообщения проекта и поиск истории. Полноту недоступных сообщений подтвердить невозможно. Действующий сайт не обследовался и не изменялся.

## Что обнаружено в 0.2.0

1. `safe_text()` вызывает `sanitize_text_field()` для body: абзацы и форматирование теряются.
2. Все статьи находятся в одном метаполе `_jz_issue_json`. Нет редактора отдельных материалов, адресов, истории правок содержимого. Поддержка revisions у CPT не версионирует это метаполе автоматически.
3. Архив выполняет `posts_per_page=-1` и разбирает JSON каждого номера на каждом показе. Рост времени и памяти пропорционален всему архиву.
4. CPT непубличный; адреса выпусков — параметры страницы, адресов статей нет. Нет собственного canonical и sitemap.
5. Номер берётся из JSON, нет атомарного счётчика и ограничения уникальности даты на уровне БД.
6. Общие права `publish_posts` и `edit_others_posts` дают импортёру лишние возможности на сайте. Любой автор с publish_posts может получить доступ к экрану проверки; отдельного редакционного допуска нет.
7. Флаг `verified` приходит из входных данных и не подтверждает проверку человека. Источники и утверждения не сопоставляются; семантика новой схемы v1 не поддерживается.
8. Блокировка охватывает wp_insert_post_data/publish, но не полноценную модель жизненного цикла, публикацию future через планировщик и прямой wp_publish_post. Сторонний доверенный PHP вообще вне границ защиты плагина.
9. Импорт ищет существующий номер, затем сохраняет без блокировки: гонки, потерянные изменения и дубли возможны. Нет ограничений частоты запросов, конфликтов версий и защиты ручных правок.
10. Нет полного безопасного жизненного цикла установки/обновления/деактивации и процедуры переноса старых данных.
11. Положительное: проверка nonce, экранирование вывода, лимит входа, импорт только в draft и запрет перезаписи опубликованного номера уже предусмотрены.

## Решение до реализации

Собственные InnoDB-таблицы с префиксом WordPress + `es_`: issues, articles, revisions, state; events, publications, article_sources, identities, relations, imports. Данные афиши, записей и темы не меняются. CPT не используется: это устраняет зависимость ручной публикации от универсальных механизмов публикации WordPress. Компромисс: собственный редактор, sitemap, поиск по редакционной очереди и история, вместо штатных экранов записей и Gutenberg.

Одна строка issue на дату (UNIQUE), отдельные строки article с постоянным slug. Рабочий JSON и одобренный публичный JSON разделены. Чтение сайта всегда из публичного снимка. Удалённая из черновика статья остаётся публичной до одобрения новой версии. Снятие выпуска с публикации — отдельное ручное действие.

Транзакции + SELECT FOR UPDATE + версия формы предотвращают гонки. Счётчик номера блокируется в той же транзакции, что публикация. Номер выдаётся при первой публикации; повторное одобрение сохраняет номер. Все проверки и изменения журнала внутри транзакции. Ошибка откатывает операцию. Последовательность номеров не означает сортировку по дате: задним числом разрешён номер с более поздним порядковым номером.

Отдельные права: es_edit, es_import, es_publish. Роли редактора и импортёра. Публиковать может только выбранная учётная запись владельца с es_edit и es_publish; по умолчанию — администратор, активировавший плагин. Публикация — только POST из административной формы, cookie + nonce + явный checkbox + текущая версия + повторная серверная проверка. Публикационного REST endpoint нет. Статусы JSON не дают прав.

JSON принимается строго по приложенной схеме с дополнительными ограничениями размера, глубины, строк, количества вложенных объектов, типов URL и ссылочной целостности. Неполные выпуски допустимы как черновики. Источники не запрашиваются сервером. Нет загрузок чужих файлов, выполнения shortcodes и LLM-запросов. HTML тела проходит разрешающий список; служебные поля не попадают в публичный снимок.

Три допустимых статуса фактов: verified_primary, verified_independent, attributed_single. unverified блокирует. Независимость проверяется структурно по dependency_group; достоверность этих данных, охват всех утверждений текстом, контекст цитат, права на фото и реальная независимость остаются ответственностью человека. Каждая статья требует ручного подтверждения именно текущего хеша.

Публичные маршруты только в `/gazeta/`. Собственный документ и локальные CSS/JS исключают воздействие темы; wp_head/wp_footer намеренно не запускаются на этих маршрутах. Поэтому аналитика и другие вставки темы автоматически сюда не попадают. Остальные страницы не меняются. Canonical, robots, Open Graph, NewsArticle/BreadcrumbList и собственный sitemap формирует плагин. Статические файлы и разметка не содержат импортных внутренних заметок.

Архив: 12 номеров, индекс по статусу/дате, ограниченный запрос; кэш через штатные transients с версией публичного каталога и TTL. Снимки черновиков никогда не кэшируются публично. Предпросмотр требует авторизации и nonce, no-store/noindex.

Макет: сохраняются типографика, цвета, бумага, шапка, колонки, мобильные точки перелома, ночной свет и размер текста. Навигация статей становится обычными постоянными ссылками, доступными без JS. Исторические демонстрационные новости не устанавливаются как реальные. При отсутствии разрешённого изображения используется нейтральная редакционная иллюстрация из предоставленного макета.

Миграция 0.2.0 — только отдельным действием, один выпуск за раз. Старый CPT и метаданные не изменяются и не удаляются; перенесённое становится непроверенным черновиком. Деактивация и удаление файлов плагина сохраняют редакционные таблицы. Восстановление предыдущей версии кода требует бэкапа: 0.2.0 не читает новую модель хранения.

## Дополнения заказчика, включённые до выпуска 0.3.0

- Единый `event_id` независим от конкретной статьи; старый `story_group_id` остаётся совместимым вспомогательным идентификатором. Для схемы 1.0 event_id заполняется из него, для 1.1 обязателен.
- Нормализованный URL источника (без фрагмента и рекламных меток), внешний ID публикации в пределах домена, SHA-256 исходного текста при наличии, отпечаток текста статьи и заголовка. Сопоставление по всему опубликованному архиву. Значения content_hash сообщает поставщик; плагин не скачивает первоисточник для перепроверки хеша.
- Одинаковый текст блокируется. Совпадение события, заголовка или источника требует явных связей с предыдущими статьями и объяснения существенного развития. Отображаются конкретные совпадения. Внутри номера повтор текста, события или URL между разными новостями блокирует допуск.
- Две версии связей — draft/public. Правка черновика не удаляет доказательную связь опубликованной версии. Импорт имеет журнал с уникальными import_id и хешами полезной нагрузки.
- Название, подзаголовок, девиз, логотип, ссылки клуба, палитра и основной шрифт вынесены в `es_appearance`. В данных настроек предусмотрены идентификаторы шаблона страницы, компоновки и карточки. В 0.3.0 поставляется один утверждённый классический шаблон. Произвольные файлы шаблонов, CSS, JS и HTML через настройки не принимаются.
- Все публичные URL начинаются с нейтрального `/gazeta/`. Название издания не участвует в идентичности материалов. Ссылки «Афиша» и «Главная» находятся только в собственной шапке газеты. Меню темы не изменяется.
