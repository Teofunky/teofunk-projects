## Что НЕ проверено и почему

- **PHP 7.4.33 и MySQL 5.7.21 в работе**, в том числе создание `wp_es_meta` через `dbDelta` и `INSERT … ON DUPLICATE KEY UPDATE` в MySQL. Нет в среде.
- **Настоящий WordPress 6.7 с темой, Yoast 21, W3 Total Cache и плагинами сайта**: медиатека в выборе обложки, предпросмотр трёх видов во фреймах (в тестовой сборке адрес предпросмотра ведёт на неработающий домен, фреймы пустые), сброс кэша W3TC, админ-панель WordPress поверх газеты.
- **Сайт клуба** — по условию ничего не устанавливалось и не менялось.
- **Полевые Core Web Vitals** (75-й перцентиль) — только с рабочего сайта; лабораторные цифры выше получены без темы, Yoast, хостинга и реальной сети.
- **Ручная доступность**: экранный диктор (VoiceOver, NVDA, TalkBack), увеличение 200 %, клавиатура в настоящем WordPress.
- **10+ материалов в номере**: формат JSON 1.1 допускает не больше 7; вёрстка номера из 10 проверена на синтетическом выпуске в обход лимита.
- **Кроссворд на настоящих телефонах (0.5.3).** Телефонный режим проверен только в Chromium с эмуляцией касаний (`isMobile`, `hasTouch`, `pointer: coarse`). WebKit (Safari) в среде нет. Поэтому на iPhone и Android нужно проверить вручную: системная клавиатура действительно не открывается при касании клетки (`inputmode=none` и отмена `mousedown`), страница не увеличивается, двойное касание клавиш не масштабирует страницу (`touch-action: manipulation`), панель стоит над нижней панелью Safari и полосой «Домой», работает переход на системную клавиатуру. Режим телефона включают касание и ширина до 699 px (или высота до 499 px в альбомной ориентации). Планшеты остаются в обычном режиме.
- **Поиск на настоящем MySQL**: `LIKE` по нормализованному тексту проверен на SQLite. Скорость на большом архиве не мерилась; оценка — ниже.
- **Морфология** — алгоритм Snowball для русского: он упрощает, иногда отрезает лишнее («винил» → «вин»), поэтому найдётся и «вино». Имена и фамилии в разных падежах находятся (проверено на пилотном выпуске). Опечатки не исправляются.
- **Кадр в настоящей медиатеке**: выбор фото через окно медиатеки WordPress и размеры `large` проверяются только на тестовой копии.
- **Тестовая копия test.kozlovclub.ru, 23.10.2026, только просмотр, ничего не сохранялось.** Владелец поставил 0.5.2 и загрузил в № 002 кроссворд «Скрытая партитура» (40 слов). Предпросмотр, открытый во фрейме шириной 375 px внутри админки, показал: сетка 23×28 px = 670 px в рамке шириной 343 px, кнопки в три ряда (180 px), строка вопроса 137 px. Отсюда 0.5.3. Тот же файл, отрисованный этой версией, даёт на 375 px клетки 15 px и всю сетку на экране.
- **Тестовая копия test.kozlovclub.ru (22.10.2026, только просмотр, ничего не сохранялось):** стоит 0.5.0, газета открыта, № 001 и № 002 опубликованы. У главного материала № 002 готовность показывает «Фото: нужны права, подпись и изображение из медиатеки этого сайта». Причина (факт): адрес фото ведёт на `kozlovclub.ru`, а сайт — `test.kozlovclub.ru`; проверка требует тот же домен (так же в 0.3.4). На рабочем сайте домены совпадут. Это же фото вертикальное (960×1440) и в рамке 3:2 обрезалось по центру — голова музыканта не попадала в кадр. Значение `50% 20%` для вертикальных фото подобрано на нём: временная правка стиля только в окне браузера, на сайте ничего не менялось.

## Как повторить

Тесты и инструменты входят в пакет разработчика `kozlov-jazzeta-0.5.4-dev.zip`.

```sh
# без браузера
sh tests/run-all.sh <выпуск JSON 1.1> <распакованный плагин 0.3.4 или 0.3.5> [<распакованный 0.4.0>] [<URL страниц>] [<распакованные 0.5.0:0.5.1:0.5.2:0.5.3>]

# с браузером: страницы и локальный HTTP-сервер
php tests/harness/render.php          <выпуск.json> <папка>/out   <URL папки плагина>
php tests/harness/render-variants.php <выпуск.json> <папка>/out   <URL папки плагина> <URL папки с тестовыми фото>
php tests/harness/render-admin.php    <выпуск.json> <папка>/admin <URL папки плагина> <URL папки с тестовыми фото>
sh tests/run-all.sh <выпуск.json> <0.3.x> <0.4.0> <URL папки> <0.5.0>:<0.5.1>:<0.5.2>:<0.5.3>
ES_CW_FILE=<кроссворд.json> php tests/harness/render.php …   # плюс crossword-file.html с вашим кроссвордом
SHOT_BASE=<URL папки>/out/ node tests/browser/a11y.js
SHOT_BASE=<URL папки>/out/ node tests/browser/perf.js
```

Тесты пишут только во временную базу SQLite и никогда не обращаются к сайту.

## Что нужно, чтобы закрыть оставшиеся риски

1. Тестовая копия сайта (Beget) с той же версией PHP, MySQL, WordPress, темой и плагинами — пройти `docs/UPGRADE-ROLLBACK.md` целиком, включая откат на 0.3.4.
2. На копии: выбрать обложку в медиатеке, заполнить блоки, поставить кадр у фото, приложить кроссворд (пример из `examples/`), опубликовать, найти материал поиском в разных формах слова, решить кроссворд на телефоне (iOS и Android: при касании клетки системная клавиатура не открывается, вводится с клавиатуры газеты, страница не увеличивается; «Печатать клавиатурой телефона» и обратно), распечатать, проверить три вида на телефоне и компьютере, предпросмотр в «Оформлении», экранный диктор.
3. После запуска на сайте — данные Search Console / CrUX для полевых метрик.

## Оценка нагрузки поиска (расчёт, не замер)

Каждый запрос — один `COUNT(*)` и один `SELECT … LIMIT 20` с `LIKE '% основа%'` по таблице `wp_es_search` без полнотекстового индекса, то есть просмотр всей таблицы.
Объём таблицы ≈ материалов в день × дней × средний размер строки ≈ 6 × 365 × 3 КБ ≈ 6,6 МБ в год.
Гипотеза (уверенность средняя): на MySQL 5.7 такой просмотр за первые годы занимает десятки миллисекунд. Если архив и поток запросов вырастут, следующий шаг — индекс FULLTEXT с парсером ngram или внешний поиск; данные для этого уже отделены в своей таблице.
