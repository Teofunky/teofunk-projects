# Отчёт проверки 0.3.0

Дата: 21 октября 2026. Статус: пакет подготовлен для приёмки на тестовой копии сайта. Это не подтверждение готовности действующего kozlovclub.ru к установке. На действующем сайте ничего не устанавливалось; Beget не подключался.

## Окружения и результат

| Окружение | Серверные проверки | Браузер/HTTP | Расширенные проверки | Всего |
|---|---:|---:|---:|---:|
| WordPress 7.1.3, PHP 8.3.6, MariaDB 10.11.7 | 50 | 45 | 39 | 134 |
| WordPress 6.4, PHP 8.3.6, MariaDB 10.11.7 | 50 | 45 | 39 | 134 |

134 разных утверждения, повторённых на двух версиях WordPress: 268 успешных проверок. Дополнительные промежуточные прогоны в эту сумму не включены. Браузер: Chromium 156.0.8078.47 через Playwright; локальные реальные WordPress/MySQL API, без подмены их функциями-заглушками. Нативный синтаксический контроль: 16 PHP-файлов; JavaScript: 3 файла; shell: run-local.sh. Локальный сервер без иных активных плагинов.

## Проверено

- Схемы 1.0/1.1, ограничение размера, неправильные даты/типы/поля, повторные ID, неизвестные ссылки фактов, небезопасные URL, XSS, абзацы и форматирование.
- Три уровня подтверждения, обязательная проверка источников, независимые цепочки, атрибуция единственного источника и человеческое подтверждение всех статей.
- Изолированные права автора/редактора/импортёра/владельца. Другой администратор не заменяет выбранного владельца. Application Password импортёра не даёт создавать обычные записи.
- Анонимный импорт запрещён; маршрута публикации REST нет; nonce, cookie и отдельный checkbox обязательны. Прямой вызов публикации без разрешения административного обработчика отклоняется.
- Повторный импорт, конфликт import_id, обязательный If-Match, устаревшие формы, защита ручных правок и опубликованных данных. **16 одновременно запущенных процессов импорта** получают один ID выпуска.
- Два параллельных ручных обработчика публикации дают разные последовательные номера. Отказ журнала аудита откатывает публикацию вместе с номером; ошибка импорта не оставляет производные события.
- Совпадения URL с tracking-параметрами, publication_id, content_hash, event_id, полных текстов по всему опубликованному архиву. Повторы URL/ID/хешей внутри статьи/выпуска. Явная связь существенного развития с прошлой новостью.
- Настоящие браузерные действия: вход, редактор WordPress, защищённый предпросмотр, утверждение, редактирование опубликованной статьи без изменения читательского снимка, снятие и повторное утверждение с сохранением номера.
- Мобильные размеры 320/390 px, планшет 768 px, компьютер 1440 px: горизонтального переполнения нет. Визуально просмотрены классическая полоса, мобильная полоса и PNG. Ночной режим, PNG 1080×1350, чтение без JavaScript.
- Смена названия через WordPress обновляет SEO title и не меняет материал/canonical. Проверены JSON-LD, публичная API-проекция, noindex/no-store предпросмотра, sitemap и 404 для несуществующих страниц/снятых материалов. Приватные заметки не выводятся.
- Ручной перенос старого номера оставляет исходную запись неизменной и создаёт только черновик; повторное копирование идемпотентно. История восстанавливает рабочую версию и снимает подтверждения. Деактивация/реактивация сохраняют данные.
- Обычные записи WordPress до и после сценария импорта идентичны.

## Найдено и исправлено до упаковки

1. Небольшое переполнение шапки на 320 px.
2. Неверный порядок регистрации подменю оформления в WordPress.
3. Недостающий резервный serif-шрифт в canvas-карточке.
4. Редкая взаимная блокировка двух импортов: INSERT IGNORE перед FOR UPDATE создавал конкурирующее повышение блокировок. Теперь служебная строка создаётся при активации, а операции сразу берут исключительную блокировку существующей строки. Повторная проверка — 16 конкурентных импортов.
5. Усилены точные проверки внешних ID и хешей публикаций внутри одного выпуска и одной статьи.

## Производительность

Синтетический архив: 1203 опубликованные строки, по 12 номеров на страницу. EXPLAIN выбирает индекс public_archive. В финальном прогоне WordPress 7.1.3 чтение второй страницы заняло 3,247 мс без transient и 0,166 мс с ним. Это единичное локальное измерение метода Repository::listing, а не время ответа сайта и не нагрузочный SLA. Число полных JSON-документов, загружаемых архивом, не растёт вместе с архивом: список выбирает только краткие столбцы.

## Границы проверки

- Настоящая тема, афиша, билетная система, SEO-плагины, Redis/Memcached, Nginx/CDN и настройки хостинга клуба не предоставлены; совместимость проверяется по STAGING-CHECKLIST.md.
- PHP 7.4 заявлен как минимальная целевая версия, но нативные прогоны выполнены на PHP 8.3.6. MySQL 8 отдельно не запускался; испытана MariaDB/InnoDB. Multisite намеренно блокируется при активации.
- Safari/iOS и Firefox отдельно не запускались. Автоматическая проверка ширины не заменяет просмотр реальных материалов на телефонах и проверку доступности человеком.
- Не выполнялись внешнее сканирование уязвимостей, пентест, большие распределённые нагрузочные испытания и проверка истинности новостей. Фикстуры явно синтетические.
- Семантические дубли, перефразирование/перевод, правдивость заявленных цепочек источников и значимость нового факта требуют редакторской проверки; ИИ не подключён.
- В журналах среды были ожидаемые ошибки БД во время моделирования отказа аудита и ошибки заблокированных внешних проверок обновлений WordPress. Ошибка блокировки из пункта выше исправлена; финальный прогон завершился успешно.
