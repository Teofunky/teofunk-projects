# ТЗ — расширенный мониторинг источников и независимый VPS

Версия: 1.0.0, 21.10.2026. Для Claude / разработчика.

## Принятое решение

- НОВЫЙ отдельный VPS в Beget Cloud для «Ежедневного стандарта». Сервер «Виджет на сайт», на котором работает «Джаз Навигатор» / n8n, НЕ изменять, НЕ использовать для газеты, НЕ создавать нагрузку и НЕ переносить его.
- WordPress `kozlovclub.ru` НЕ переносить на VPS и не изменять тему, кассу, афишу или другие плагины. VPS выполняет только сбор, анализ, генерацию и передачу редакционного JSON в отдельный API плагина, после утверждения архитектуры.
- Собственные таблицы газеты + версия JSON 1.1, ручная редактура, запрет публикации с сервера, неизменность опубликованных номеров, учёт ручных правок.
- Реестр `sources-registry-v1.json` — **список кандидатов**, а не готовые интеграции. Все выключены по умолчанию. Изначальный список = 30 + дополнительные тематические источники.

## Облачный сервер

ОС: Ubuntu 24.04 LTS (доступна в официальном каталоге Beget). Название `ezhednevny-standard-collector`.
Начальная **проектная оценка**: 2 vCPU / 2 ГБ RAM / 25–30 ГБ SSD/NVMe, SSD фактически выбрать из доступных конфигураций. 2 vCPU / 4 ГБ использовать лишь при доказанной необходимости. IPv4 включить, IPv6 необязателен. Отдельные автоматические бэкапы/мониторинг. Размещение: регион с доступом к источникам, проверить из выбранного региона, не обещать универсального доступа.

Цена зависит от конкретной конфигурации и IP. Официальный пример для 1 vCPU / 1 ГБ / 10 ГБ: 11 ₽/сутки + 5 ₽/сутки IPv4 = 16 ₽/сутки (пример с текущей страницы Beget, **не цена рекомендуемых 2vCPU/2ГБ**). Перед нажатием «Создать сервер» показать итоговую цену из панели. Это платное действие владельца, **пока не выполнено**.

### Создание в панели Beget

1. https://cp.beget.com/cloud/create — «Виртуальный сервер», не «Приложение n8n».
2. Выбрать Ubuntu 24.04, отдельно от проекта/сервера «Виджет на сайт». Назвать `ezhednevny-standard-collector`.
3. Выбрать параметры, сеть, бэкапы и SSH-ключ. Проверить стоимость в панели. Для безопасности предпочтителен SSH по ключам, не публиковать ключи или пароли.
4. Только владелец подтверждает создание и оплату. Зафиксировать IP, конфигурацию, дату и стоимость, но НЕ сохранять секреты в ТЗ.
5. После создания сделать baseline проверку `uname -a`, `cat /etc/os-release`, `free -h`, `df -h`, `python3 --version`, проверить резервные копии.

### Первичная настройка (после доступа, отдельным проверяемым изменением)

- Регулярные обновления безопасности, не использовать root для приложения; системный пользователь `standard` без shell где возможно.
- SSH-ключ, отключение паролей только **после проверки** успешного входа новым пользователем и наличия восстановления через Beget VNC.
- Firewall UFW: входящий 22/tcp только с IP администратора, если IP стабилен (иначе отдельное решение), доступ приложению извне не нужен. При отсутствии фиксированного IP оставить 22/tcp с ключами и Fail2ban по решению владельца.
- Приложение только исходящими HTTPS к разрешённым источникам, Beget AI Gateway и `https://kozlovclub.ru`; базовая доставка по HTTPS. Не открывать веб-панель сборщика в Интернет.
- Файлы `.env` и секреты `0600`, владелец `standard`. Логи не содержат ключей или полного текста чужих статей. Регулярная очистка временных данных.
- Systemd timers для расписания: сначала запуск вручную; Cron/timer только после двух успешных тестов, с `flock`, retry, метриками, журналом, алертом.
- Снапшот перед обновлениями и установка через versioned release / rollback. Отдельный тестовый режим `dry-run`.
- Secrets: разные ключи Beget AI Gateway и WordPress application password с минимальными правами импортёра; лимит расходов контролировать на стороне Beget.

## Автоматический конвейер

1. Обходить **только прошедшие проверку** источники по расписанию; хранить ETag и Last-Modified.
2. Создавать карточки сигналов: `event_id`, источник, URL, опубликовано, замечено, автор, описание, связанные артисты, дата события, точность извлечения, допустимость использования.
3. Дедупликация URL (канонизация), приблизительных заголовков и сущностей события + окно времени; не считать репост подтверждением от независимого источника.
4. Ранжирование: культурная/музыкальная значимость, свежесть, независимое подтверждение, географический баланс, оригинальность, ограничения интересов издателя.
5. Фактчек: первичный сайт артиста/лейбла/фестиваля; не придумывать прямые цитаты, не основывать статью исключительно на социальной реакции; отмечать неподтверждённые детали.
6. ИИ через Beget AI Gateway получает только нужные метаданные и проверенные разрешённые фрагменты; не слать целиком чужие публикации без прав. Обязательная структура JSON 1.1 и серверная валидация.
7. Если недостаточно фактов — не публикуем и не «дополняем» выдумками. 4–7 хороших материалов ориентир, допускается меньше.
8. Сохранить JSON в приватном хранилище VPS. ПЕРВАЯ фаза — только выгрузка файла и ручной импорт. ВТОРАЯ — импорт с минимально привилегированным API-пользователем исключительно в черновик.
9. Все публикации — только в WordPress вручную владельцем; генератор не может подменять API, менять опубликованный снимок или публиковать.
10. Отдельная панель здоровья источников: latest_success, недоступные сайты, причины исключения, стоимость ИИ, задержка, количество сигналов и новостей.

## Правовые и продуктовые ограничения

- Наличие открытого сайта не означает разрешение копировать тексты/изображения. Приоритет RSS, APIs и публичные метаданные; ссылки обязательны, прямые цитаты только в пределах применимых прав.
- Права на фото/обложки/видео проверять отдельно. Ссылки на YouTube — не разрешение на скачивание или аудиотранскрипцию.
- Reddit: разрешение для коммерческого API обязательно. Исключить из автоматической обработки до заключения условий: https://support.reddithelp.com/hc/en-us/articles/14945211791892-Developer-Platform-Accessing-Reddit-Data
- Facebook: чужие публичные Page posts и разрешения API требуют отдельной проверки, не обходить проверки доступа.
- Telegram: Bot API не является универсальным способом получить историю чужих каналов. Сначала подтвердить законный метод для конкретного канала.
- YouTube Data API: `channels.list`/`playlistItems.list` с ограничениями квоты, не подставлять угадываемые channel_id: https://developers.google.com/youtube/v3/docs/playlistItems/list
- VPS безопасно изолирован от основного WordPress и существующего сервера «Джаз Навигатора».

## Тесты и критерии приёмки

1. Тест RSS минимум 10 проверенных новостных источников и минимум 5 официальных лейблов; реальный HTTP и парсинг.
2. 1–2 канала YouTube с реальными channel_id через API, проверка квоты и формата результата.
3. Никаких исходящих обращений к `localhost`, RFC1918, link-local, metadata endpoints через URL источников. Доказанный SSRF egress policy + ограничение redirect.
4. Нет дублирования при повторном запуске и когда заголовки разных СМИ об одном релизе отличаются.
5. Удалённый сервер не имеет способа публиковать; WordPress REST endpoint `import` отказывает для опубликованного и при конфликте версий.
6. Соответствие JSON 1.1 и тестовые кейсы недействительных дат, источников, цитат, неполного выпуска, пустых событий.
7. Запись лога ошибки/уведомление после неуспешного прогона без потери предыдущего черновика.
8. Ресурсный лимит и отказ от автоперезапуска при массовом количестве запросов.
9. Проверка на копии WordPress в PHP 7.4 / WP 6.7.2 / MySQL 5.7.21 (на основании отчёта Claude, подтвердить по живому серверу). Только после стендовой проверки работа с реальным сайтом.
10. Переход в продакшен по ручному разрешению владельца.
