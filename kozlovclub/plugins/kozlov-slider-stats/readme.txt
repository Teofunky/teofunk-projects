=== Kozlov Slider Stats (Слайдер в Метрике) ===
Version: 1.0.1
Requires at least: 5.6
Requires PHP: 7.4

Показывает в Яндекс Метрике, как работает слайдер на главной kozlovclub.ru: показы слайдера и каждого слайда,
листания, клики и кнопки покупки, отдельно для десктопа, планшета и телефона.
На телефоне отдельно: «Живой фасад», «Театр теней» и обычный слайдер (если фасад выключен).

Плагин ничего не меняет на странице: не трогает тему, слайдер, фасад, афишу и виджет Ticketscloud.
Скрипт только слушает клики и касания и вызывает ym() того же счётчика 44419291.

Установка
1. СНАЧАЛА в Метрике создать 6 целей типа «JavaScript-событие» (условие «совпадает»):
     Слайдер: показ                                   kzsl_view
     Слайдер: показ слайда                            kzsl_slide_view
     Слайдер: листание                                kzsl_swipe
     Слайдер: клик                                    kzsl_click
     Слайдер: кнопка покупки                          kzsl_buy
     Слайдер: кнопка покупки на следующей странице    kzsl_buy_next
   Цель считает события только с момента создания, а параметры события, пришедшего раньше своей цели,
   в отчёт «Параметры событий» не попадают (так написано в справке Метрики).
2. Плагины → Добавить новый → Загрузить плагин → kozlov-slider-stats.zip → Активировать (при обновлении с 1.0.0:
   «Заменить текущую версию загруженной»). Плагин сразу работает для всех посетителей, кэш W3 Total Cache сбрасывается сам.
3. Проверка без отправки в Метрику: открыть https://kozlovclub.ru/?kzsl=debug на телефоне и на компьютере.
   Внизу экрана появится тёмная панель с событиями. Режим держится во вкладке и на следующих страницах
   (кликнуть по слайдеру, перейти на страницу концерта, нажать «Купить билет»: в панели будет kzsl_buy_next).
   Выключить: открыть любой адрес сайта с ?kzsl=stop.
4. Настройки → «Слайдер в Метрике»: общий выключатель, номер счётчика, «не учитывать редакторов»,
   «кнопка покупки на следующей странице». Там же таблица целей и подсказки по отчётам.

Что уходит в Метрику (параметры событий в ветке «Слайдер на главной», 5 уровней)
  вариант (Десктоп, Планшет, Телефон · фасад, Телефон · театр теней, Телефон · обычный слайдер)
    → «Показ слайдера» → «слайдов: 3»                                         цель kzsl_view
    → «Показ слайда» → адрес слайда → «№2 · НАНИ ЕВА · 31 дек»                 цель kzsl_slide_view
    → «Листание» → стрелки / вкладки / точки / свайп / перетаскивание          цель kzsl_swipe (первый способ), остальные параметрами
    → «Клик» → адрес слайда → Купить билет / Регистрация / Бронь стола / Картинка / Название / Кнопка «…»   цель kzsl_click
    → «Кнопка покупки» → адрес слайда → тип кнопки                             цель kzsl_buy
    → «Кнопка покупки после клика» → адрес слайда → этот же концерт / другой концерт   цель kzsl_buy_next
- Адрес слайда: адрес страницы, на которую ведёт слайд. Концерт: его slug (nani-eva-skazochnyj-novyj-god),
  WordPress не даёт двум записям одинаковый slug, повторный концерт получает -2, -9 и т. д. Лендинг: novyj-god.
  Джазета: gazeta. Другой сайт: адрес сайта и путь. Адрес одинаковый на десктопе и телефоне.
- «Показ» = слайдер хотя бы наполовину на экране (или занимает половину экрана) не меньше 1 секунды.
  «Показ слайда» = слайд был текущим 1 секунду, пока слайдер на экране. На десктопе слайды листаются сами.
- Кнопка покупки на следующей странице: клик по слайдеру запоминается во вкладке на 2 часа (sessionStorage).
  Цель уходит, только если после клика посетитель перешёл на другую страницу. «Этот же концерт» решает
  ID Ticketscloud кнопки; адрес страницы сравнивается, только если у кнопки нет ID.
- Все кнопки покупки: это нажатие, а не оплата. Оплату считает Ticketscloud (цели «Получение оплаты», «Ecommerce: покупка»).

Как читать
1. Отчёты → Технологии → Устройства, цели «Слайдер: показ» и «Слайдер: клик»: CTR = визиты с кликом / визиты с показом.
2. Отчёты → Содержание → «Параметры цели», цель «Слайдер: показ слайда», потом «Слайдер: клик»:
   показы и клики каждого слайда по вариантам. CTR слайда = клики / показы.
3. Оплаты: в отчёте «+» рядом с «Люди» → Поведение → Параметры визита → «Слайдер на главной» → вариант → «Клик»,
   затем цели «Получение оплаты» (order.paid_online) и «Ecommerce: покупка». Сравнить с тем же сегментом
   по «Показ слайдера». Это связь, а не доказательство, что продажу дал слайдер.

Что нового в 1.0.1 (по внешнему аудиту 1.0.0)
- События ждут Метрику до 20 секунд, если её код опоздал. На живом сайте тема объявляет ym() в <head>,
  поэтому в 1.0.0 события там не терялись; очередь страхует от оптимизаторов, которые переносят этот код.
- Новая цель kzsl_slide_view: показы каждого слайда теперь цель, а не только параметры.
- Стабильный адрес слайда вместо названия с датой. ID записи WordPress в разметке слайдера и фасада нет,
  добавить его можно только правкой темы и фасада; slug тоже уникален в WordPress, его хватает.
- kzsl_buy_next только после настоящей смены страницы: кнопка в афише той же главной больше не считается.
  «Этот же концерт» по ID Ticketscloud, а не по адресу страницы.
- Каждый способ листания (стрелки, вкладки, точки, свайп, перетаскивание) уходит отдельно, раз за просмотр
  страницы; цель kzsl_swipe по-прежнему одна, на первый способ.
- Режим ?kzsl=debug пишет клики в свою память (kzsl_click_debug), держится во вкладке до ?kzsl=stop.
  Вошедший редактор не оставляет в памяти ничего, поэтому после выхода из аккаунта его клики не всплывут.
- Видимость через IntersectionObserver: проверка раз в 0,5 с работает, только пока слайдер на экране и вкладка
  открыта, и останавливается совсем, когда показаны все слайды. На других страницах скрипт сразу завершается,
  если в этой вкладке не было клика по слайдеру.
- Клики, сделанные скриптом (isTrusted = false), не считаются.
- Названия целей и параметров: «кнопка покупки», а не «покупка».
- Не принято: «одна и та же цель регистрируется не чаще раза в секунду». В справке Метрики по reachGoal
  и в разделе лимитов такого правила нет (лимиты там: 512 параметров за визит, 8 КБ на запрос, 10 уровней).
  Показы слайдов и так идут не чаще раза в секунду: слайд должен простоять текущим 1 секунду.

  ym() не появилась 23 с (очередь сброшена без ошибок), кнопка афиши на той же главной (цели нет), тот же адрес
  с другим ID Ticketscloud («другой концерт»), одинаковые адреса слайдов на десктопе и телефоне, debug и редактор
  не пишут в память, клик скриптом не считается, другая страница без клика не вешает обработчики, слайдер вне
  экрана 11 с при автопрокрутке не даёт показов, после возврата показы идут дальше. Ошибок JavaScript нет.
- Не проверено: установка внутри WordPress kozlovclub.ru с W3 Total Cache и Kozlov Perf. По коду Kozlov Perf 1.2.2
  встроенные скрипты не откладывает и не меняет; на живой главной JS-минификации W3 Total Cache нет
  (скрипты грузятся по исходным адресам). После установки проверить через ?kzsl=debug на телефоне и компьютере.

Известные ограничения
- Оплата идёт внутри виджета Ticketscloud, и Метрика часто записывает её отдельным визитом, который начинается
  на ticketscloud.com: с 27.10 по 26.11.2026 так было у 854 из 1 543 визитов с целью «Получение оплаты».
  Поэтому «клик по слайдеру → оплата» смотрим по людям. Ticketscloud передаёт в виджет идентификатор посетителя
  Метрики (параметр ym-uid в коде tcwidget.js), поэтому оплата должна привязываться к тому же человеку.
  Это вывод из кода виджета, его надо проверить на данных через неделю.
- Выручки по каждому слайду нет: сумма заказа известна только Ticketscloud, плагин её не видит.
- Метрика отправляет цель обычным запросом. Если клик ведёт на другую страницу, запрос может оборваться
  переходом; Метрика хранит неотправленные запросы (_ym_retryReqs) и досылает их на следующей странице сайта.
  Если посетитель сразу ушёл с сайта, такой клик может потеряться.
- Посетители с блокировщиком, который режет Метрику, не считаются (как и во всей Метрике).
- Отчёт «Параметры визитов» считает визиты, «Параметры цели» и «Параметры событий» считают события.
