=== Kozlov Perf ===
Version: 1.2.2
Requires: WordPress 6.3+, PHP 7.4+

Изолированный плагин оптимизации загрузки kozlovclub.ru.
Не меняет файлы темы, базу, афишу и другие плагины. Работает только на фронте:
снимает лишнее из очереди скриптов WordPress и правит готовый HTML страницы.

== Что делает (всё включается/выключается в Настройки → Kozlov Perf) ==

1. Нативная ленивая загрузка. Разметка a3 Lazy Load (заглушка + data-src,
   включая <source data-srcset> в <picture>) возвращается к обычной, его JS/CSS
   не грузятся. Первые N картинок страницы (по умолчанию 8: логотип, слайдер,
   первый ряд афиши) грузятся сразу, остальным ставится loading="lazy"
   decoding="async". Разметка внутри script, noscript, style, template,
   textarea и HTML-комментариев не трогается; символ > внутри атрибутов
   обрабатывается корректно.
   Превью для retina (1.2.0): см. пункт 12.
2. Easy FancyBox и YouTube Embed Plus убираются со страниц, где они не нужны.
   FancyBox остаётся, если есть хоть одна ссылка, которую он может перехватить:
   класс/rel/data с fancybox, href на картинку, PDF, SWF, YouTube, Vimeo,
   Dailymotion (ссылки на конкретное видео, не на канал). YouTube Embed Plus остаётся, если есть его embed (классы
   __youtube_prefs__/epyt-) или шорткод [embedyt]. Закомментированная разметка
   и noscript в решении не участвуют.
3. Список «не подключать» (по умолчанию jquery.animateNumber, в теме его вызов
   закомментирован): снимается из очереди WordPress и вырезается из HTML, то есть
   работает и для скриптов, вписанных в шаблон темы напрямую. jQuery в список
   попасть не может.
4. defer для скриптов из списка (по умолчанию список пуст) через штатную
   стратегию загрузки WordPress 6.3+: ядро само проверяет зависимости и
   inline-хвосты и при конфликте не применяет defer.
5. Отключение wp-emoji.
6. Preconnect к fonts.googleapis.com, fonts.gstatic.com, mc.yandex.ru,
   top-fwz1.mail.ru, ticketscloud.com.
7. Чистка head: RSD, wlwmanifest, shortlink, meta generator, заголовок
   X-Powered-By.
8. Исправление задвоенного параметра ver в адресах (…?ver=X&ver=X).
9. Дубли: одинаковые <script src> (с учётом type) и <link rel=stylesheet>
   (с учётом media: print и screen это разные подключения); комментарии и
   noscript не учитываются. Open Graph: для og:url/title/type/description/
   locale/site_name остаётся первый непустой тег; повторная og:image (тот же
   URL) удаляется вместе со своими og:image:width/height/type; разные картинки
   с одинаковыми размерами не затрагиваются.
10. CSS блоков Гутенберга: выключено по умолчанию, включать после проверки.
11. Мобильные (1.1.0): из meta viewport убираются user-scalable=no, maximum-scale,
    minimum-scale (пинч-зум разрешён; iOS игнорировал запрет и раньше, на Android
    он мешал увеличивать текст). Кнопкам, ссылкам и полям ставится
    touch-action: manipulation (отклик без задержки, без зума по двойному тапу,
    пинч остаётся). Полям ввода на тач-экранах font-size 16px, чтобы iOS не
    увеличивал страницу при фокусе. Отдельная галочка «Мобильные».

12. Превью нужного размера (1.2.0). До 1.2.0 у превью (src вида …-450x338.jpg)
    srcset убирался целиком, и карточка афиши шириной 330–470 px на retina-экране
    (нужно 660–940 точек) получала файл 450 px, растянутый в 1,5–2 раза: мыло.
    Теперь в srcset остаются только:
    - варианты не шире 1024 px (настройка), тяжёлые большие оригиналы не попадают;
    - варианты, у которых рядом лежит WebP. WebP Express собирает <picture>, только
      если WebP есть для каждого варианта, поэтому браузер получает WebP весом
      в десятки килобайт (карточка 800 px: 19–71 КБ), а не JPEG/PNG до 850 КБ.
      Нет WebP у самого превью: srcset убирается, как в 1.1.0;
    - из почти одинаковых по ширине (разница меньше 10 %) больший: оригинал 800 px
      вместо нарезки 768 px (он и чётче: сжат один раз, а не дважды).
    Карточкам афиши (size-category-thumb2) ставится sizes по замеру раскладки темы,
    ленивым картинкам впереди sizes добавляется auto (Chrome берёт вариант по
    фактической ширине). Обычный экран по-прежнему берёт превью 450 px.
    Превью без srcset (например, «Ещё в этот вечер» на странице концерта) получают
    его по вложению WordPress: поиск по адресу файла, кеш на сутки, не больше 40
    поисков на страницу.
    На картинке ставится метка data-kperf="srcset": по ней Kozlov Afisha Week 1.0.4+
    оставляет srcset в отложенных карточках.
    Режимы в настройках: «оставлять лёгкие варианты» (по умолчанию), «убирать»
    (как 1.1.0), «не трогать». Настройки 1.1.0 переносятся: снятая галочка
    «убирать srcset» становится «не трогать».

13. 1.2.1: порядок с WebP Express и скорость.
    WebP Express запускает два буфера: внутренний (template_redirect, 10000) работает
    раньше Kozlov Perf, внешний (init, 1) позже всех. Внутренний собирает <picture>,
    если WebP есть у всех вариантов srcset, и тогда браузер берёт <source>.
    - <picture> от WebP Express: список ограничивается и в <source>, и в <img>, sizes
      одинаковый. Варианты берутся из самого <source> (там «адрес.webp», WebP Express
      уже проверил файлы), диск не проверяется. В 1.2.0 на каждый промах кэша
      страниц уходило около 1200 проверок файлов: 460–545 мс на сервере Beget.
    - Картинки без <picture>: WebP проверяется только у вариантов, которые иначе
      попали бы в srcset.
    - Ранний проход (template_redirect, 0): снаружи плагинов, которые собирают
      страницу в своём буфере (Kozlov Event Page, приоритет 1). Дописывает srcset
      превью, которые основной проход не видел: «Ещё в этот вечер», фото артистов.
      В коде страницы отдельный комментарий «Kozlov Perf 1.2.1 late: …», если было
      что менять. Работает в режиме «оставлять лёгкие варианты» с включённым
      «Добавлять srcset превью, у которых его нет».
    Время обработки главной на стенде: 1.1.0 17 мс, 1.2.0 33 мс (плюс диск),
    1.2.1 41 + 2 мс. На сервере это примерно в 4,4 раза больше.

14. 1.2.2: свой кеш вариантов. Замер на сайте после 1.2.1 показал, что время уходит
    в основном на поиск вложения по адресу файла (attachment_url_to_postid): на Beget
    это 60–70 мс на запрос, на главной 10 таких превью, на странице концерта 4.
    Кеш объектов W3TC (Redis) попаданий не даёт, поэтому результат теперь хранится в
    своей опции kozlov_perf_fill_cache (не автозагружается): адрес превью → srcset
    WordPress. Найденное хранится неделю, «не найдено» сутки. Опция пишется только
    при промахе кеша страниц и только если появились новые превью; больше 3000
    записей: начинается заново. Очищается при сохранении настроек и при удалении
    плагина. В комментарии страницы db_lookups=N: сколько поисков было на ней.

== Что плагин НЕ делает ==

- Не объединяет счётчики и пиксели, которые вставляются через JavaScript
  (два top.mail.ru, два VK, заглушки 'VALUE' в сниппете Rating@Mail.ru):
  это правится в теме вручную.
- Не кеширует страницы, не конвертирует в WebP, не меняет число карточек на
  главной и объём чат-виджета. Это отдельные задачи.

== Защита от ошибок ==

- Исключение PHP внутри обработчика возвращает исходный HTML без изменений.
- Каждый шаг проверяет результат регулярного выражения; при сбое шаг
  пропускается, страница отдаётся в прежнем виде.
- Логические ошибки замены исключением не являются, поэтому они покрыты
  набором из 23 проверок (картинка внутри JS-строки, > в атрибуте,
  закомментированные теги, print/screen, группы og:image, <picture>,
  скрипты в шаблоне, ссылки с пробелами, YouTube/PDF-ссылки, noscript).
- Снятие скриптов из очереди происходит до обработки HTML и от неё не зависит.
- Время обработки страницы с 300 карточками: ~13 мс (PCRE JIT), ~43 мс без JIT.

== Установка ==

1. Плагины → Добавить новый → Загрузить плагин → kozlov-perf.zip → Установить → Активировать.
2. Настройки → Kozlov Perf: менять ничего не нужно.
3. Рекомендуется деактивировать a3 Lazy Load (плагин его заменяет). Можно и
   оставить: его разметка всё равно возвращается к обычной, скрипты не грузятся.

== Проверка ==

- Главная, страница концерта, Джазета: картинки, слайдер, видео, кнопки
  Ticketscloud, поиск и фильтры афиши, на компьютере и телефоне.
- В исходном коде перед </body> есть комментарий <!-- Kozlov Perf 1.1.0: … -->
  с тем, что сделано на этой странице (сколько картинок отложено, что убрано,
  что оставлено).
- Любая страница с ?kperf=off показывается без оптимизаций (для сравнения).
- Если используется кеш-плагин: после активации сбросить кеш.

== Откат ==

Снять галочку «Плагин включён» или деактивировать плагин. Файлы темы и
другие плагины не затронуты.
