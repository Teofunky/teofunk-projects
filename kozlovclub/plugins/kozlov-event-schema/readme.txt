Разметка schema.org MusicEvent (JSON-LD) для страниц концертов kozlovclub.ru.

== Описание ==

Добавляет в <head> страниц будущих концертов один блок JSON-LD (MusicEvent, для лекций и мастер-классов EducationEvent): название, дата и время (по Москве), сцена (MusicVenue) и адрес, описание, картинка, жанры (keywords), исполнители (performer), цена, ссылка на покупку и начало продаж. Организатор связан с Organization из разметки Yoast (#organization).

Данные только читаются из полей, которые уже заполняют редакторы:
* дата и время, стоимость: календарь All-in-One Event Calendar;
* сцена: флажки location_main_scene, location_mansarda, location_the_beat, location_myasnitskaya;
* описание: «Текстовый блок №1» (textblock_1_description);
* продажа билетов: ticketscloud_link;
* жанры: genre_categories;
* картинка: изображение записи;
* исполнители: строка состава в текстовых блоках анонса (textblock_1_description, textblock_2_description, additional_text_description, artist_description), например «На сцену выйдут: Дмитрий Илугдин (фортепиано), Пётр Ившин (ударные).»;
* начало продаж (validFrom): дата публикации анонса.

Тема, афиша и данные анонсов не меняются. Плагин хранит свою настройку и, только если редактор сам заполнил их в блоке «Для поисковиков», скрытые поля у этого анонса: _kozlov_event_status и _kozlov_event_previous_start (статус «Отложен», «Перенесён на новую дату» или «Отменён») и _kozlov_event_performers (исполнители, вписанные вручную).

Правила:
* «от N руб.» и «N руб.»: цена N ₽, если заполнена ссылка Ticketscloud (наличие билетов не указывается);
* «Вход свободный»: бесплатное событие (цена 0);
* «Депозит ...»: без цены;
* не отмечена сцена: адрес ул. Маросейка, 9/2;
* «Отложен» (новой даты нет): EventPostponed, прежняя дата; разметка выводится и после этой даты;
* «Перенесён на новую дату»: EventRescheduled, новая дата из календаря, прежняя в previousStartDate, цена остаётся;
* «Отменён»: EventCancelled, дата и место остаются; разметка выводится и после этой даты;
* при любом статусе остальные свойства (цена, место) не меняются, как требует Google;
* статус в блоке виден только поисковикам: в тексте анонса его нужно написать самому;
* разметка не выводится для черновиков, событий с паролем, повторяющихся и уже прошедших (кроме отложенных и отменённых);
* исполнители: пары «Имя (роль)» после слов «выйдут:», «в составе:», «примут участие:», «состав:», «гость:», «ведущий:» и т. п.; варианты «X или Y» пропускаются; вписанные вручную заменяют найденные в тексте, «-» отключает;
* validFrom: дата публикации анонса, только если она раньше начала концерта;
* availability (наличие билетов) не выводится: плагин не знает, распроданы ли билеты.

== Установка ==

1. Плагины → Добавить новый → Загрузить плагин → выбрать zip → Установить → Активировать.
2. Настройки → Разметка концертов: проверить таблицу и просмотр разметки.
3. Включить флажок «Выводить разметку», сохранить, очистить кэш страниц (Performance → Purge All Caches).

При обновлении поверх предыдущей версии настройка сохраняется: если вывод был включён, он останется включённым.

Выключение: снять флажок или деактивировать плагин. Удаление стирает только данные плагина (настройку, поля статуса и исполнителей).

= 1.2.0 =
* performer: исполнители из строки состава в тексте анонса («На сцену выйдут: Имя (инструмент), …»), тип Person.
* В блоке редактора (теперь «Для поисковиков») поле «Исполнители»: вписать вручную (по одному на строке) или «-», чтобы не выводить.
* offers.validFrom: дата публикации анонса.
* Страница проверки: столбец «Исполнители» и счётчик анонсов без найденного состава.

= 1.1.2 =
* Исправлено: отложенные и отменённые концерты больше не пропадают из разметки после исходной даты.
* Страница проверки показывает все отложенные и отменённые независимо от даты.
* Цена при отмене, отсрочке и переносе не убирается (по правилам Google меняется только eventStatus).
* В блоке статуса предупреждение: статус нужно продублировать в тексте анонса.
