# Правки темы KozlovCLub, 13.10.2026

Два файла темы: `wp-content/themes/KozlovCLub/single.php` и `index.php`. Остальное в теме не меняется.

## Что изменено
single.php:
1. Предпросмотр черновиков. Черновик попадает в выборку событий только при предпросмотре и только для пользователя, который может его редактировать. Для остальных запрос прежний.
2. Ссылки «предыдущий / следующий концерт» и «другие даты» ведут сразу на /event/имя/, а не на /ru/event/имя (было: переадресация, потом адрес без слэша).
3. Два вызова implode с аргументами в старом порядке (устарело в PHP 7.4, в PHP 8 страница концерта падает с ошибкой). Вывод не меняется.

index.php:
4. Ссылки на концерты на главной так же ведут на /event/имя/.
5. Параметр ?view= принимает только line или cell. Было: в адрес можно было подставить свой HTML/скрипт, и он выводился на странице (уязвимость XSS).

Построчно: changes.diff.

1. Любой будущий опубликованный концерт: дата, цена, кнопка «Купить», ссылки «предыдущий / следующий» ведут на /event/имя/.

## Как проверено
- Синтаксис: php -l (PHP 8.3, short_open_tag=On, как на сайте), совместимость с PHP 7.4+ через PHPCompatibility: замечаний нет (в оригинале single.php было 2, про implode).
- Локальный WordPress 6.7.2 с заглушкой темы (header/footer, _month, _day, WPGlobus) и тестовыми событиями в таблицах календаря:
  - черновик в предпросмотре у админа: было пусто, стало с текстом и правильной датой;
  - черновик без входа: 404 до и после;
  - черновик не попадает в «следующий концерт» у опубликованного;
  - ссылки: было /ru/event/имя, стало /event/имя/;
  - ?view="><script>...: в оригинале скрипт выводился на странице, в новой версии нет.
- Не проверено: на PHP 7.4 (локально 8.3) и на реальном календаре All-in-One Event Calendar (таблицы заполнены вручную). Что у черновика есть строка с датой, следует из кода календаря 2.3.4.
