## Как устроена история

- Каждая версия плагина или темы восстановлена из своего ZIP-архива отдельным коммитом. Дата коммита (author date) взята по самому новому файлу внутри архива, в описании коммита указан архив-источник.
- Каждая версия отмечена тегом `<папка>/v<версия>`, например `kozlov-event-page/v1.0.15`. Получить файлы версии: `git checkout kozlov-event-page/v1.0.15`.
- В основной ветке лежит самая старшая версия. У плагинов с двумя линейками (1.0.x для текущего сайта и 1.1.x и выше для нового) версия для текущего сайта доступна по тегу.
- У `kozlov-afisha-filters` линейки шли параллельно: 1.1.0 и 1.1.1 (новый сайт) собраны 3–4 ноября, раньше, чем 1.0.9–1.0.11 (текущий сайт, 5 ноября). В истории версии идут по номерам.
- Если один номер версии встречался в нескольких архивах с разным содержимым, взят архив с более новыми файлами, остальные перечислены в описании коммита.

## Чего здесь нет

- `kozlov-import/data/`: выгрузка контента из дампа базы от 22.10.2026. В ней контакты артистов и сотрудников, поэтому в репозиторий она не попадает. Готовые ZIP с данными остаются на Mac.
- `kozlov-import-cache-1` и `-2`: архивы картинок для импорта, это не код.
- `kozlov-jazzeta`: плагин Джазеты живёт в репозитории [Teofunky/jazzeta-pipeline](https://github.com/Teofunky/jazzeta-pipeline).

## Остальное

- `themes/current-theme`: снимок темы текущего сайта (прежний разработчик), `themes/current-theme-patches`: правки к ней.
- `tools/diagnostics` и `tools/wp-snippets`: скрипты диагностики и служебные сниппеты для текущего сайта.
- `tests/`: тестовые стенды плагинов.
- `docs/2026-10-13-status`: сводка состояния работ на 13 октября 2026.
