Перекрёстная валидация при загрузке: компонент индекса не может ссылаться на

**Схема БД**

22 таблицы в шести схемах, 5 представлений, 10 триггеров, 2 point-in-time
функции. Миграция 0001 проверена на прямом и обратном проходе; autogenerate
расхождений не показывает.

**Слой доказательств**

- Контентно-адресуемое хранилище (локальное и S3), запись через временный файл
  с переименованием, файлы доказательств read-only на диске.
- `ProvenanceWriter`: снимок и наблюдения в одной транзакции, идемпотентность по
  ключу «источник + запрос + день + хеш содержимого».
- `IngestRunner`: проверка разрешений, ограничение частоты, ретраи, деградация.

**Тесты: 137, все проходят.** Из них 20 проверяют, что сама БД отвергает
нарушение принципов, а не то, что Python об этом просит.

### Phase 2: адаптеры источников (частично)

Четыре адаптера по источникам, доступ к которым уже разрешён:

| адаптер | что решает |
|---------|------------|
| `CbrKeyRateAdapter` | шаговый ряд: дни без решения заполняются с флагом `forward_filled`, дни до первого известного решения помечаются как отсутствующие |
| `CbrFxAdapter` | выходные: ЦБ отвечает пятничными курсами на запрос за субботу, адаптер фиксирует отсутствие, а не дату пятницы |
| `OpenMeteoAdapter` | архив (факт) и прогноз (forecast) никогда не смешиваются; неполный вечер это отсутствие, а не среднее по тому, что пришло |
| `ProductionCalendarAdapter` | маркеры `*` и `+`: сокращённый и перенесённый дни остаются рабочими |

Плюс: HTTP-клиент с классификацией отказов (429 и 503 повторяются, 403 и 404
нет), проверка robots.txt, команды `barometer ingest run|all|status` и
`barometer observations show`, оффлайн-демо на фикстурах.

Живыми ответами сервисов парсеры ещё не проверены: в окружении сборки исходящий
трафик к этим хостам заблокирован. Тесты идут на фикстурах, воспроизводящих
формат (кодировка windows-1251, запятая как разделитель, обёртка ASMX DataSet).
Первый живой запуск и есть настоящая проверка. Несовпадение формата не потеряется:
runner сохранит сырой ответ как доказательство и запишет ошибку разбора.

## Принципы: где именно они закреплены

| принцип | механизм |
|---------|----------|
| 1. Числа считает код | роль `barometer_agent` без INSERT в `model`/`feature`; валидатор `agents.yaml` |
| 2. Барометр воспроизводим | `model.model_run` хранит параметры, версию кода, окно обучения |
| 3. Факт / метрика / оценка / гипотеза / прогноз | тип `registry.assertion_class` + поле `measures` |
| 4. Провенанс у каждого наблюдения | `norm.observation.snapshot_id` NOT NULL |
| 5. Доступность это не продажи | `measures='inferred'` -> максимум `estimate`, триггер БД |
| 6. Корреляция это не причинность | режим `lag_correlation` требует предупреждения и десезонализации |
| 7. Все винтажи прогнозов хранятся | триггер append-only на `model.forecast` |
| 8. Нет утечки будущего | CHECK `feature_vintage <= forecast_created_at`; функции `*_as_of` |
| 9. Слух это не событие | `norm.information_attention` с CHECK, запрещающим `fact` |
| 10. robots.txt и условия использования | `enabled` требует разрешённого robots; `respect_robots` нельзя выключить |

## Текущие допущения

1. **Индекс не откалиброван.** Пока нет рыночного ряда транзакций, интерфейс
   говорит «Оценка внешнего спроса». YoY публикуется как движение индекса.
2. **Панель площадок выключена.** Ни одна площадка не проверена на robots.txt и
   условия использования. Сбор по ним невозможен до ручной проверки.
3. **Ёмкость залов нигде не заполнена.** Ограничение БД не позволяет записать
   ёмкость без URL источника. Данные надо найти и сослаться.
4. **Python 3.11, 3.12 или 3.13.** Проверено сквозным прогоном на каждом.
   На 3.14 pydantic 2.13 падает на изменённом механизме аннотаций
   (`_eval_type() got an unexpected keyword argument 'prefer_fwd_module'`).
   Makefile выбирает подходящий интерпретатор сам; `make doctor` предупреждает,
   если доступен только непроверенный.
5. **TimescaleDB опционален.** В окружении разработки его нет, используется
   BRIN. В production ожидается TimescaleDB.

синтетическая.

## Известные ограничения

- Парсеры четырёх адаптеров не проверены на живых ответах. См. выше.
- Python 3.14 не поддерживается, пока pydantic не выпустит совместимую версию.
  Базовые зависимости сведены к тому, что код реально импортирует (восемь
  пакетов), чтобы установка ломалась как можно реже; polars, pandas, numpy,
  fastapi и uvicorn перенесены в extras своих фаз.
- `ops.source_health.expected_freshness_hours` заполняется из каденции
  источника грубо. Для `cbr_key_rate` каденция `irregular`, поэтому свежесть
  показывается как `unknown`: у ряда решений нет ожидаемого интервала.
  Точные ожидания появятся после наблюдения реальных задержек публикации.
- Диффы афиш (`norm.event_diff`) описаны в схеме, но детектор ещё не написан.
- Схемы ввода-вывода агентов (`schemas/agent/*.json`) объявлены в
  `config/agents.yaml`, но файлы появятся в Phase 8 вместе с исполнителем.
- Промпты агентов в `prompts/` содержат системные инструкции и границы; без
  исполнителя они не активны.
