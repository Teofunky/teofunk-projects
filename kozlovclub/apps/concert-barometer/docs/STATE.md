Перекрёстная валидация при загрузке: компонент индекса не может ссылаться на
необъявленный ряд, ряд на несуществующий сегмент, агент на неизвестный источник.

**Схема БД**

22 таблицы в шести схемах, 5 представлений, 10 триггеров, 2 point-in-time
функции. Миграция 0001 проверена на прямом и обратном проходе; autogenerate
расхождений не показывает.

**Слой доказательств**

- Контентно-адресуемое хранилище (локальное и S3), запись через временный файл
  с переименованием, файлы доказательств read-only на диске.
- `ProvenanceWriter`: снимок и наблюдения в одной транзакции, идемпотентность по
  ключу «источник + запрос + день + хеш содержимого».
- `IngestRunner`: проверка разрешений, ограничение частоты, ретраи, деградация.

**Тесты: 85, все проходят.** Из них 20 проверяют, что сама БД отвергает
нарушение принципов, а не то, что Python об этом просит.

## Принципы: где именно они закреплены

| принцип | механизм |
|---------|----------|
| 1. Числа считает код | роль `barometer_agent` без INSERT в `model`/`feature`; валидатор `agents.yaml` |
| 2. Барометр воспроизводим | `model.model_run` хранит параметры, версию кода, окно обучения |
| 3. Факт / метрика / оценка / гипотеза / прогноз | тип `registry.assertion_class` + поле `measures` |
| 4. Провенанс у каждого наблюдения | `norm.observation.snapshot_id` NOT NULL |
| 5. Доступность это не продажи | `measures='inferred'` -> максимум `estimate`, триггер БД |
| 6. Корреляция это не причинность | режим `lag_correlation` требует предупреждения и десезонализации |
| 7. Все винтажи прогнозов хранятся | триггер append-only на `model.forecast` |
| 8. Нет утечки будущего | CHECK `feature_vintage <= forecast_created_at`; функции `*_as_of` |
| 9. Слух это не событие | `norm.information_attention` с CHECK, запрещающим `fact` |
| 10. robots.txt и условия использования | `enabled` требует разрешённого robots; `respect_robots` нельзя выключить |

## Текущие допущения

1. **Индекс не откалиброван.** Пока нет рыночного ряда транзакций, интерфейс
   говорит «Оценка внешнего спроса». YoY публикуется как движение индекса.
2. **Панель площадок выключена.** Ни одна площадка не проверена на robots.txt и
   условия использования. Сбор по ним невозможен до ручной проверки.
3. **Ёмкость залов нигде не заполнена.** Ограничение БД не позволяет записать
   ёмкость без URL источника. Данные надо найти и сослаться.
4. **Python 3.11 как нижняя граница.** Целевой рантайм 3.12; код не использует
   ничего новее 3.11.
5. **TimescaleDB опционален.** В окружении разработки его нет, используется
   BRIN. В production ожидается TimescaleDB.

## Нерешённые вопросы доступа к источникам

Это главный блокер Phase 2. Каждый пункт требует человека, а не кода.

| источник | что нужно | блокирует |
|----------|-----------|-----------|
| `yandex_wordstat` | подтвердить хост API и схему авторизации; id региона для Москвы; получить токен | весь компонент «Поисковый спрос» |
| `rosstat_emiss` | проверить robots.txt fedstat.ru; зафиксировать id показателей | реальные доходы, платные услуги, общепит |
| `cbr_inflation` | зафиксировать id наборов данных в `cbr.ru/dataservice` | дефлятор для реальных цен |
| `sberindex` | проверить условия использования; предпочесть лицензионное соглашение парсингу | компонент «Потребление и общепит» |
| `mos_data` | зарегистрировать API-ключ; найти id наборов по мероприятиям | компонент «Событийный стресс» |
| `moscow_transport_restrictions` | проверить robots.txt; найти официальный RSS/API | ограничения мобильности |
| `venue_public_pages` | юридическая проверка ToS по каждой площадке; robots.txt | вся конкурентная панель |
| `ticketscloud_owned` | подтвердить доступ к API и разрешённое хранение сырых ответов | калибровка и бэктест |

Ни один из них не обойдён заглушкой с выдуманными данными. Там, где источник
недоступен, существует интерфейс адаптера и фикстура, явно помеченная как
синтетическая.
