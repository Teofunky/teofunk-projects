# План реализации

Фазы из мастер-спецификации, с конкретикой и критериями готовности.
Статус на 21.09.2026: Phase 0, Phase 1 и первая половина Phase 2 выполнены.

---

## Phase 0: репозиторий и архитектурные решения. **Выполнено**

Структура, зависимости, локальный стек одной командой, `docs/ARCHITECTURE.md`,
10 ADR.

---

## Phase 1: схема БД, реестр источников, провенанс. **Выполнено**

22 таблицы, 5 представлений, 12 триггеров, 2 point-in-time функции. Реестры с
перекрёстной валидацией. Контентно-адресуемое хранилище снимков. Runner с
проверкой разрешений, ретраями и деградацией.

---

## Phase 2: адаптеры Wordstat, ЦБ, погоды и официальной статистики. **Частично**

**Разрешённые: сделано.** Четыре адаптера написаны и покрыты тестами:

| адаптер | источник | что делает |
|---------|----------|------------|
| `CbrKeyRateAdapter` | `cbr_key_rate` | ключевая ставка, шаговый ряд |
| `CbrFxAdapter` | `cbr_fx` | курсы USD/RUB и EUR/RUB, только рабочие дни |
| `OpenMeteoAdapter` | `open_meteo` | два отдельных ряда: архив и прогноз |
| `ProductionCalendarAdapter` | `production_calendar` | праздники, сокращённые и перенесённые дни |

Критерий MVP «минимум четыре работающих адаптера» закрыт по коду. Остаётся
проверка на живых ответах: в окружении сборки эти хосты недоступны.

**Ожидают человека.** Wordstat, Росстат, СберИндекс, данные Москвы: для каждого
создаётся интерфейс адаптера, фикстура с явной пометкой `synthetic` и точная
инструкция по получению доступа. Живые данные не выдумываются.

Готовность: адаптеры проходят тесты на записанных ответах, суточный запуск
идемпотентен, здоровье источников отражается в `ops.source_freshness`.

---

## Phase 3: реестр площадок и суточные снимки с диффами

Блокируется юридической проверкой по каждой площадке. Схема готова:
`norm.event_observation` и `norm.event_diff`.

Работа: детектор диффов, нормализация `event_key` (площадка, приведённое
название, дата), классификация изменений, поле `ambiguity_note` для случаев,
где изменение страницы неотличимо от изменения рынка.

Готовность: суточный снимок площадки даёт устойчивый `event_key` между днями,
переверстка страницы не создаёт ложных «новых» событий.

---

## Phase 4: исторический бэкфилл с 2024 года

Через тот же `ProvenanceWriter`. Ручные выгрузки регистрируются как снимки с
`legal_basis='user_supplied'`. Винтаж бэкфилла это дата загрузки, а не дата
наблюдения: иначе бэктест получит знание из будущего.

Готовность: повторный запуск бэкфилла ничего не дублирует, а
`norm.observation_as_of` на любую прошлую дату даёт согласованную панель.

---

## Phase 5: признаки и сезонная база

Календарные признаки (единственные с `calendar_exempt`), STL-декомпозиция,
робастное шкалирование, флаги выбросов, лаги.

Готовность: каждый признак несёт `max_input_available_at`; тест доказывает, что
признак невидим для `feature_as_of` до момента доступности входов.

---

## Phase 6: первый индекс NOW и моментум

Динамическая факторная модель с оценкой загрузок по EM; равновзвешенная
стандартизованная схема как запасной вариант, пока истории меньше 24 месяцев.
Нормализация к 100 на базовом окне. Отклонение от сезонной нормы, WoW.
Оценка уверенности из свежести, покрытия, волатильности пересмотров.

Готовность: индекс считается за любую прошлую дату из данных, доступных на эту
дату; вклады компонентов берутся из загрузок, а не назначаются.

---

## Phase 7: ансамбль прогнозов и скользящий бэктест

Сезонная наивная модель как обязательный бенчмарк, структурная модель
пространства состояний, градиентный бустинг с лаговыми экзогенными признаками.
Веса ансамбля из обратной MAE на бэктесте. Rolling origin: 365 дней обучения,
шаг 7 дней, минимум 26 фолдов. Покрытие интервалов измеряется, а не
декларируется.

Готовность: ни одна модель не публикуется, не побив сезонную наивную на
скользящем бэктесте; каждый прогноз сохранён как винтаж и неизменяем.

---

## Phase 8: агенты, верификация и red team

Исполнитель агентов с провайдерской абстракцией, схемы ввода-вывода в
`schemas/agent/`, контракт вывода (провенанс и класс утверждения обязательны),
эвалы из `config/agents.yaml`.

Готовность: агент, нарушивший контракт, отклонён, и нарушение записано в
`ops.agent_invocation.contract_violations`; блокирующая проверка
останавливает публикацию.

---

## Phase 9: API и дашборд

FastAPI поверх представлений. Next.js, ECharts. Слои-чекбоксы из
`config/segments.yaml`, пять режимов просмотра, нормализация к 100 при
сравнении разнородных рядов, запрет общей оси для разных классов единиц.
Страница методологии, страница точности прогнозов, страница свежести данных.

Готовность: любое число на экране раскрывается до источника и снимка;
неопределённость видна без дополнительного клика.

---

## Phase 10: расписание, мониторинг, алерты, бэкапы, эвалы

Prefect или Dagster, структурные логи и трассировка, алерты по устареванию
источников и по провалам блокирующих проверок, бэкапы БД и объектного
хранилища, регулярный прогон эвалов агентов.

Готовность: суточный конвейер идёт без вмешательства, а его отказ виден раньше,
чем его заметит пользователь.

---

## Критерий готовности MVP

Из мастер-спецификации, с текущим состоянием:

| критерий | статус |
|----------|--------|
| одна команда поднимает локальный стек | выполнено (`make bootstrap`) |
| минимум четыре работающих адаптера | код готов, ждёт живой проверки |
| воспроизводимый исторический бэкфилл | Phase 4 |
| идемпотентный суточный конвейер | механика готова, проверена тестами |
| провенанс у всех наблюдений | выполнено, ограничение БД |
| NOW и моментум считаются | Phase 6 |
| прогноз с наивным бенчмарком и бэктестом | Phase 7 |
| винтажи прогнозов неперезаписываемы | выполнено, триггер |
| данные конкурентов помечены как прокси | выполнено, тип и триггер |
| дашборд показывает свежесть и неопределённость | Phase 9 |
| суточная сводка на русском из структурных данных | Phase 8 |
| автоматические тесты проходят | выполнено, 137 тестов |
