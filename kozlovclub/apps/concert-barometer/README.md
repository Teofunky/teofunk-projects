# Концертный барометр

Независимая система внешней рыночной аналитики и прогнозирования платного
вечернего досуга в Москве: концерты, клубы, залы, театры, стендап, фестивали,
общепит.

Система измеряет **среду**, в которой работает площадка, а не продажи самой
площадки. Она отвечает на вопрос «каким был рынок в этот вечер», чтобы вопрос
«хорошо ли мы сработали» имел точку отсчёта.

**Состояние:** Phase 0, Phase 1 и первая половина Phase 2 выполнены. Схема БД,
реестры, провенанс, конвейер сбора и четыре адаптера реальных источников
работают и покрыты тестами (137). Индекс и прогноз это Phase 5-7.
Подробности: [`docs/STATE.md`](docs/STATE.md).

## Как запустить

Нужны **Python 3.11+** и **Docker** (только чтобы поднять PostgreSQL).
Проверить, чего не хватает: `make doctor`.

```bash
tar -xzf concert-barometer.tar.gz
cd concert-barometer
make bootstrap
```

`make bootstrap` создаст виртуальное окружение, поставит зависимости, поднимет
PostgreSQL с TimescaleDB и MinIO, применит миграции и зальёт реестры. Файл
`.env` не обязателен: значения по умолчанию совпадают с `docker-compose.yml`.

Дальше:

```bash
make demo      # весь конвейер на фикстурах, сеть не нужна
make ingest    # собрать четыре разрешённых источника (нужна сеть)
make test      # 137 тестов
```

`make demo` прогоняет боевой путь целиком (проверка разрешений, runner, запись
провенанса, триггеры БД, представления) и подменяет только сетевой вызов. Это
способ увидеть систему работающей, не дожидаясь доступа к источникам.

### Без Docker

Если PostgreSQL 14+ уже где-то есть:

```bash
createdb barometer
export BAROMETER_DATABASE_URL='postgresql+psycopg://user:pass@localhost:5432/barometer'
make bootstrap-no-docker
```

TimescaleDB опционален: без него схема использует BRIN-индексы
([ADR 0008](docs/adr/0008-timescaledb-is-optional.md)).

### Команда barometer

После установки она лежит в `.venv/bin`. Либо активируйте окружение
(`source .venv/bin/activate`), либо вызывайте напрямую:

```bash
./.venv/bin/barometer config validate
```

### Если что-то пошло не так

| симптом | причина |
|---------|---------|
| `docker: command not found` | поставить Docker Desktop или идти путём без Docker |
| `Cannot connect to the Docker daemon` | Docker установлен, но не запущен |
| `connection refused` на 5432 | БД не поднялась: `docker compose ps` |
| `barometer: command not found` | окружение не активировано, см. выше |
| `ingest` падает с ошибками сети | источники недоступны из вашей сети, проверьте `make demo` |

## Что отличает эту систему

**Числа считает код, а не языковая модель.** Агенты собирают, проверяют и
объясняют. Барометр и прогноз считает воспроизводимый статистический код. Это
не договорённость: у роли `barometer_agent` нет права INSERT в схемы `model` и
`feature`.

**Число без источника не существует.** Ссылка на снимок сырого ответа не
допускает NULL. Любое опубликованное значение раскрывается до URL, времени
получения, периода наблюдения и SHA-256 исходных байтов.

**Ревизия это новая строка.** Наблюдения, признаки, индексы и прогнозы
append-only. На вопрос «что мы знали 1 марта» система отвечает правдиво.

**Доступность билетов это не продажи.** Что ряд вправе заявить, определяется
полем `measures` (`direct` / `derived` / `inferred`), и это проверяется
триггером БД, а не дисциплиной разработчика.

**Пока нет калибровки, нет слова «продажи».** Интерфейс говорит «Оценка
внешнего спроса». База отвергает прогноз, помеченный как рыночные продажи, без
ссылки на калибровочный прогон.

## Команды

```bash
barometer config validate      # загрузить и перекрёстно проверить реестры
barometer config sources       # список источников и их статус доступа
barometer db sync-registry     # спроецировать config/*.yaml в registry.*
barometer db status            # ревизия миграции, TimescaleDB, счётчики строк
barometer venues review        # что ещё требует проверки доступа
```

## Законность доступа

Источник не выбирается, а допускается. Порядок: объявить с `enabled: false`,
проверить robots.txt и условия использования, записать результат, и только
после этого включить. Валидатор не позволяет включить источник с неразрешённым
статусом, а настройку `respect_robots` нельзя выключить.

Панель площадок поставляется **полностью выключенной**. Каждая площадка требует
отдельной юридической проверки. Список того, что ждёт человека, находится в
[`docs/STATE.md`](docs/STATE.md) и выводится командой `barometer venues review`.

## Десять принципов

Они не комментарии, а ограничения. Где закреплён каждый: таблица в
[`docs/STATE.md`](docs/STATE.md).

1. LLM собирают, классифицируют, проверяют и объясняют. Числовой барометр они
   не изобретают.
2. Барометр и прогноз считает воспроизводимый статистический код.
3. Факт, производная метрика, оценка, гипотеза и прогноз различаются явно.
4. Каждое наблюдение хранит источник, endpoint, период, географию, единицу,
   время получения, методологию и хеш снимка.
5. Доступность билетов конкурента никогда не называется продажами.
6. Причинность не выводится из корреляции.
7. Хранятся все исторические винтажи прогнозов.
8. В бэктестах нет утечки будущего.
9. Политика и общественные темы излагаются фактически и нейтрально. Слух это
   не факт.
10. robots.txt, условия использования, ограничения частоты и закон соблюдаются.
