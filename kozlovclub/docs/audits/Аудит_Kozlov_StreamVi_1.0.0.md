# Аудит Kozlov StreamVi 1.0.0

**Объект:** `kozlov-streamvi-1.0.0.zip`, 21 элемент в ZIP, 16 PHP-файлов включая заглушки index.php, 1 JS-файл, 1 CSS-файл.
**Тип проверки:** локальный аудит исходников + `php -l` для всех PHP-файлов (PHP 8.4.24), `node --check` JS (Node 22), изолированные PHP-тесты логики и HTTP-макет. На реальном WordPress/StreamVi/БД концертов и с реальными OAuth-токенами не тестировался.

**Итог:** недостаточно надёжен для неконтролируемого автопереименования действующих трансляций. До включения на основном сайте устранить блокирующие пункты ниже.

## P0 — блокирующие

### P0-1. OAuth: неправильный первичный формат запроса
**Файл:** `includes/class-kzsv-api.php:43–59`, `:176–183`.
**Факт:** `exchange_code()` сначала шлёт JSON. Официальная инструкция StreamVi предписывает `POST /site/oauth/token` как `application/x-www-form-urlencoded`. Повтор с формой происходит только при ошибке HTTP 400 или 415. Если JSON отвергается 422, корректного повтора нет. В изолированном тесте с ответом 422 (JSON) / 200 (form) воспроизведено: произведена одна JSON-попытка, подключение не состоялось.
**Исправление:** сразу использовать форму; не отправлять client_secret, пока не проверено, что он нужен текущему контракту. Проверить по документации обязательность и формат каждого поля и результат реального OAuth на тестовом проекте.
**Документ:** https://streamvi.io/ru/docs/dev/api

### P0-2. Проверка живого эфира не соответствует документированному быстрому старту
**Файл:** `includes/class-kzsv-api.php:104–119`, `includes/class-kzsv-api.php:14`, `includes/class-kzsv-runner.php:133–144`.
**Факт:** код делает `GET /method/broadcast/status` с `broadcast:read`; в официальной инструкции StreamVi для определения текущего эфира указан `GET /method/project/live-status` с `project:read`. Не подтверждено, что `/method/broadcast/status` вообще существует в действующем API, а парсер `kind/status/date_start` соответствует его ответу.
**Исправление:** проверить точный endpoint и схему живого статуса в актуальном справочнике; использовать подтверждённый метод и необходимые scope; протестировать ответы для активного эфира, паузы, потери соединения, отсутствия эфира и ошибок/нестандартного JSON. Не объявлять статус «не идёт» при неизвестной структуре ответа.
**Документ:** https://streamvi.io/ru/docs/dev/api

### P0-3. Защита действующей трансляции может разрешить опасную смену названия
**Файлы:** `includes/class-kzsv-engine.php:92–106`, `includes/class-kzsv-runner.php:133–157`.
**Факты, подтверждённые тестами:**
- Если информация об эфире недоступна (`$live === null`), `guard()` возвращает `true` — переключение разрешено (`unknown`). При ошибке API плагин явно пишет «Переключаю по расписанию».
- Если начало *какого угодно* прямого эфира позднее планового момента переключения (`started >= target.act`), код считает эфир «своим», без подтверждения соответствия концерту. Тест: следующий концерт 21:00, его `act` 20:00, чужой эфир начался 20:05: `guard()` возвращает `true, own`.
- За 10 минут до нового концерта переключение принудительно разрешено, даже при действующем чужом эфире (`deadline`). Это заложено настройками, но противоречит абсолютному обещанию «Идущий эфир не трогается» на странице администратора.
**Исправление:** выбрать явно политику безопасности. По умолчанию fail-closed при ошибке статуса, без предположения по одной дате старта, без автоматического forced-switch в активном эфире. Если бизнес-требование — гарантия названия к началу следующего концерта, сделать эту опасную опцию явно включаемой, с текстовым предупреждением. Сверять идентификатор трансляции, если API это позволяет.

## P1 — серьёзные

### P1-1. «Уже отправляли» не означает «сейчас совпадает»
**Файл:** `includes/class-kzsv-runner.php:109–119`; интерфейс: `includes/class-kzsv-admin.php:424–437`.
**Факт:** если ключ и хеш последней отправки совпадают, `run()` сразу возвращает `ok`, не сверяя фактическое название StreamVi. Внешняя ручная правка в кабинете, другой интегратор или расхождение между площадками остаются невосстановленными.
**Исправление:** периодически считывать текущее состояние StreamVi; при расхождении повторять отправку только после проверки защиты живого эфира. Показывать статус `не совпадает`, а не `Работает`.

### P1-2. Часовой пояс берётся из WordPress, а не закреплён за московской афишей
**Файлы:** `includes/class-kzsv-settings.php:93–107`, `includes/class-kzsv-source.php:202–209`, `:224–272`.
**Риск:** в данных ai1ec исходное время в UTC трактуется как «настенные часы афиши» и пересчитывается через `wp_timezone()`. Если часовой пояс сайта UTC, а афиша живёт по Москве, переключение произойдёт со сдвигом на 3 часа. Настройки реального WordPress и конкретные SQL-значения не предоставлены, поэтому наличие ошибки на сайте **не подтверждено**.
**Исправление:** явно задать и показать timezone клуба (`Europe/Moscow`), проверить три реальных события (дата/начало) из базы и сравнить с фронтендом/админкой. Не менять обработку ai1ec наугад без реального SQL-примера.

### P1-3. Отсутствие безопасного переключения между источниками афиши
**Файл:** `includes/class-kzsv-source.php:45–68`, `:297–299`.
**Риск:** в режиме `auto` первое обнаруженное наличие типа записи `concert` и таксономии `kc_stage` приводит к выбору `core`, даже если будущая новая система ещё не заполнена. Существующий ai1ec игнорируется, график пустеет.
**Исправление:** при миграции явно фиксировать `ai1ec` либо проверять полноту и достоверность данных в источнике, прежде чем менять автоматически.

### P1-4. Тестовый режим не гарантирует отсутствия изменений
**Файлы:** `includes/class-kzsv-runner.php:218–239`, `includes/class-kzsv-admin.php:538`, `:571`.
**Факт:** метод ручной отправки `send_now()` не проверяет `dry_run` и `enabled`: «Поставить сейчас» отправит реальное обновление даже при включённом тестовом режиме. Пользователь может полагаться на пояснение «в StreamVi ничего не менять».
**Исправление:** в тестовом режиме отключить реальные ручные отправки или явно реализовать отдельное действие с подтверждением опасного обхода.

### P1-5. Ошибки исполнения не всегда попадают в оповещения
**Файл:** `includes/class-kzsv-runner.php:45–59`.
**Факт:** исключение верхнего уровня только логируется и откладывает новую проверку на 10 минут. В `KZSV_Notify::problem()` оно не попадает, и админка может показывать «Работает».
**Исправление:** устанавливать активную ошибку `runtime`, уведомлять администратора, автоматически снимать при успешном цикле.

## P2 — исправить до принятия финальной версии

- **Лимиты описания:** `includes/class-kzsv-source.php:101–117` — длинный `desc_suffix` способен превысить `desc_max`, поскольку обрезка основы использует `max(50, $room)`. Обрезать все итоговое описание после подстановок в строгий лимит либо заранее резервировать место для суффикса и валидировать длину самого суффикса.
- **Название YouTube:** `includes/class-kzsv-settings.php:67` позволяет `title_max=255`, хотя в админке указано 100. Если внешняя площадка действительно ограничивает название 100 символами, нельзя предлагать 255 без предупреждения/валидации.
- **Метабокс-превью даты:** `includes/class-kzsv-metabox.php:52` передаёт `time()` вместо времени начала концерта. При `{date}` и `{time}` превью будет неверным.
- **Секрет в URL:** `includes/class-kzsv-cron.php:143–179`, `includes/class-kzsv-admin.php:592–594` — REST-маршрут GET с `key=` в строке запроса; ключ может попадать в access-логи и внешние системы. Предпочесть POST с ключом в заголовке, с запретом кэширования и ротацией ключа.
- **OAuth-сессия:** `includes/class-kzsv-admin.php:122–158` — `state` однократный, но при callback не проверяется, что пользователь сейчас авторизован под тем же аккаунтом и имеет `manage_options`. Рекомендуется привязать операцию к сессии администратора согласно инструкции StreamVi.
- **Блокировка:** `includes/class-kzsv-runner.php:320–341` — устаревший lock удаляется по одному timestamp, а `unlock()` удаляет по имени, не по владельцу. При процессах дольше 120 секунд возможна гонка. Сделать lock с уникальным токеном владельца и compare-and-delete.
- **Проверка WP-Cron:** `includes/class-kzsv-admin.php:582–589` — надпись «работает» по одному факту задания не доказывает исполнение. Сверять последний `last_tick` и плановый срок с grace period.
- **Отзыв секрета и удаление:** `disconnect` очищает локальный токен, но не отзывает внешний доступ; `uninstall.php` необратимо удаляет метаданные событий, включая ручные названия/описания. Необходимо явно документировать и продумать резервное сохранение данных.

## Что хорошо

- PHP-синтаксис всех файлов корректен, проверен `php -l`.
- JavaScript синтаксически корректен, проверен `node --check`.
- WP nonce и `manage_options` применяются к административным действиям.
- При записи метабокса проверяются nonce и права `edit_post`.
- Вывод в админке в основном корректно экранирован (`esc_html`, `esc_attr`, `esc_url`).
- Запросы к SQL с внешними значениями параметризованы, операции с афишей — чтение.
- Секреты шифруются через sodium или OpenSSL при наличии расширения; одноразовое OAuth `state` и PKCE присутствуют.
- Есть журнал, retry, защита от одновременных запусков, WP-Cron и внешняя резервная точка запуска.
- `GET /method/broadcast/template` соответствует найденному описанию в актуальном справочнике StreamVi.

## Обязательные проверки перед production

1. OAuth с тестовым проектом: точный формат тела, доступные scopes, проверка успешного token/context.
2. Фактический статус в StreamVi: прямой эфир, offline, pause, lost, ошибка 4xx/5xx, неожиданная структура ответа.
3. Безопасность: не переименовывать на чужом live при любой ошибке статуса и при позднем старте трансляции; проверить принудительную смену впритык к концерту.
4. Сверить по 3–5 реальным `ai1ec_event_instances` `start/end` и московской афише, включая после полуночи.
5. Подтвердить, что `bulkUpdate` реально меняет нужные названия/описания на необходимых площадках, и ничего постороннего.
6. Два концерта подряд, две сцены, перенос начала/окончания, отмена, `skip`, ручной override, редактирование анонса.
7. При внешней ручной правке StreamVi плагин должен обнаружить расхождение и безопасно восстановить синхронизацию.
8. Убедиться, что `dry_run` никогда не отправляет изменения, включая ручную кнопку.
9. Отключённый WP-Cron, отсутствие ночных посещений, недоступность StreamVi, 429 и потеря сети: проверка повторов и почтовых оповещений.
10. Только после успешной проверки включать автоматизацию в production, иметь кнопку мгновенной паузы и журнал фактических действий.

**Ограничение достоверности:** из архива можно проверить логику, синтаксис, источники и вызовы. Нельзя доказать корректность реальной интеграции и конкретных времён концертов без доступа к WordPress, SQL и тестов с токеном StreamVi. Часть пунктов P1/P2 — подтверждённые кодовые дефекты, часть — потенциальные риски, требующие проверки конфигурации.
